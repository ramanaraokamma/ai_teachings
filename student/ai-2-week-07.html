Main lesson · Section 2

Read the activity-duration contract

Use the same meaning and unit in every row.

One session per row

A fictional classroom logs the duration of each activity. Before comparing durations, define a schema: activity is nonempty text, minutes is an integer from 0 through 60, and each row describes one activity session.

These decisions make data interpretable.

What the contract does and does not require

A row represents one session; a column represents the same named field across sessions. A schema is the table’s written contract. Here minutes means whole minutes, including 0 and 60. Nonempty means at least one character in this simple example; a spaces-only name would pass the code, so a stricter real application needs an explicit whitespace rule.

Main lesson · Section 3

Check presence, type and range separately

The supplied Python example assumes both fields exist.

Read the complete validator

rows = [{"activity": "Reading", "minutes": 12},
        {"activity": "Sorting", "minutes": 0}]
for row in rows:
    valid = (type(row["activity"]) is str
             and len(row["activity"]) > 0
             and type(row["minutes"]) is int
             and 0 <= row["minutes"] <= 60)
    print(valid)

Explain each check

A schema is a checklist for what a row must contain. First ask whether the activity name is text and is not empty. Next ask whether minutes is an integer.

Then ask whether that integer lies between 0 and 60, including both ends. Keep these checks separate when explaining a rejection.

The number 12 and the text "12" look similar on a page, but only the number meets this lesson’s minutes rule.

The worked script prints True twice. type(value) is int checks the exact type here and avoids accepting a Boolean as a count. The chained comparison checks both boundaries. The example assumes both keys exist; this week’s paper audit identifies missing fields without treating this script as a complete missing-field validator. A zero duration is allowed by this written schema.

      rowOne record or example in a table.
      columnA table field containing the same kind of information across rows.
      data typeA category of values, such as number, text or Boolean, with defined operations.
      schemaA specification of required fields, types and structural rules for data.

      TypeA category such as integer or text
      UnitThe quantity scale attached to a number
