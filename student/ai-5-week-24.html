Student lesson · 2 of 16

Notice the evidence

Return to the binary image task: class 1 means the left column sum is strictly larger than the right column sum; equal sums belong to class 0. Let d be left sum minus right sum. An augmentation is useful only under a stated task and transformation rule. More image files do not automatically mean more independent evidence.

Operation on rows [1, 0] and [0, 0]Result rowsdClass
Original[1, 0] and [0, 0]11
Swap top and bottom rows[0, 0] and [1, 0]11
Swap left and right columns[0, 1] and [0, 0]-10

Swapping rows preserves each column sum, so it preserves this task label for every valid image. Swapping columns changes d to -d. For nonzero d the class changes; for d = 0 it stays class 0. Blindly copying the original label after every flip would create incorrect training targets.

A transformation may be valid for one task and invalid for another. A crop can remove the evidence needed for a label. Choose allowed transformations using the task definition and training evidence, document the assumptions, and evaluate the choice on validation data.

Student lesson · 3 of 16

See how it works

This code assumes valid 2 by 2 binary lists. It constructs new lists instead of changing the input. The label function encodes the classroom task rule, not a general method for recovering unknown real-world labels.

def difference(x):
    return x[0][0] + x[1][0] - x[0][1] - x[1][1]

def label(x):
    return int(difference(x) > 0)

def swap_rows(x):
    return [x[1][:], x[0][:]]

def swap_columns(x):
    return [row[::-1] for row in x]

x = [[1, 0], [0, 0]]
assert label(x) == label(swap_rows(x)) == 1
assert label(swap_columns(x)) == 0
tie = [[1, 0], [0, 1]]
assert label(tie) == label(swap_columns(tie)) == 0
assert x == [[1, 0], [0, 0]]

If an allowed transformation changes a known target, the transformed example needs a justified new label. Do not invent labels for ambiguous cases. Keep the source ID, transformation and resulting label with every derived image so a teacher can audit what happened.

Student lesson · 7 of 16

Find and repair a mistake

Week 23 used deliberately constructed toy images. Its validation E is exactly a row-swapped version of training A, and F is a row-swapped version of C. They had different pixel arrays, but the transformation relation means they are a weak independence test for an experiment that trains on row-swapped variants. If those variants are added, they become exact training-validation duplicates. Preserve the original narrow claim and design a new grouped split for the augmentation experiment.

Source groups should match the evaluation question. If the goal is generalisation to new objects or people, several photographs of the same object or person may need one group even when they have different original file IDs. A lineage audit catches recorded relationships; an exact-pixel audit catches duplicates with inconsistent IDs. Neither audit alone proves that all dependence has been removed.

When a leak is discovered after validation has influenced choices, repair the split and rerun training and selection. Do not merely rename or remove the overlapping files and keep claiming the old score evaluates the repaired experiment. Final data that influenced decisions is no longer reserved.
