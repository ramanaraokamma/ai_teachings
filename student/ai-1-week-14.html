Main lesson · Section 3

Validate, stop if rejected, then predict

Record the model version even when its threshold was not reached.

Trace accepted and missing-height paths

Apply the input checks in order

For every record, first check that a height is present and its stated unit is cm. Then check that it is a whole number from 1 through 10.

If any check fails, record no prediction and the reason, then stop processing that record. Do not continue into the threshold comparison.

Predict only after every check passes

If all checks pass, compare the height with 6. At least 6 gives the prediction tall; otherwise give short. Record the original input, model version Tower1 and the prediction.

For a rejected record, record the original input, Tower1, no prediction and a reason. Tower1 identifies the intended model even when its threshold was not used.

CORE IDEA Classification maps features to a category using a decision boundary.

UNDER THE HOOD A classifier partitions feature space into decision regions. A decision boundary is where the predicted category changes.

Different boundaries may fit the same training examples but behave differently on unseen or borderline inputs.

Sixty millimetres equals six centimetres, but this version accepts cm records only. It does not contain a conversion step.

Main lesson · Section 7

No prediction is a recorded system outcome

It is neither a hidden short prediction nor a decision about what a person must do.

Keep the later action separate

The classifier reports a prediction or no prediction. It does not decide what a person must do with a tower.

A separate classroom procedure might ask someone to remeasure a rejected input or compare a prediction with a recorded label. Write that action separately from the predicted category.

Retain rejected records in the system evidence

No prediction is not a third tower size. It records that this procedure did not assign short or tall.

Count and investigate such records when evaluating the whole system; hiding them could make a system look more useful than it is.

Repair the validation-equals-correctness claim

  • CLAIM A Anything on the same side must truly belong to that category.

  • CLAIM B Only one possible boundary can fit the examples.
