Notice the evidence

A fictional activity sorter labels a supplied integer duration. Negative values are Invalid; values from zero through 12 are Short; larger values are Long. The labels describe duration only. Write this requirement before the program so that a test has an expected answer independent of the code.

An if statement selects a block when its condition is true. An elif is considered only if earlier conditions in the same chain were false. An else handles the remaining cases. Colons end the condition lines. Use four spaces for the indented statements and keep related branches aligned.

Student lesson · 3 of 16

See how it works

minutes = 12
if minutes < 0:
    label = "Invalid"
elif minutes <= 12:
    label = "Short"
else:
    label = "Long"
print(label)

The output is Short. For 12, the first condition is false and the second is true. The else block is skipped. print(label) is not indented, so it runs after the selected branch. Each path assigns label before this line reads it. Change only minutes and save before each fresh run.

These tests exercise every branch and the equality case. A change from <= 12 to < 12 is exposed by 12; testing 11 alone misses it. Branch coverage means every branch was exercised, but it does not prove every condition is correct.

A pictorial worked case: Branching and boundary tests

Check invalid values before branching. A toy shelf label uses fewer than five books as "small", otherwise "large", but negative counts are invalid.

The facts we will use

Python 3: if count<0: label="invalid"; elif count<5: label="small"; else: label="large". Read as indented branches.

Why this result follows

An if/elif/else chain selects the first matching branch. Putting invalid handling first prevents a negative count from being mislabelled as a small valid collection.

What this example does not establish

The toy procedure assumes numeric counts; validate types and define missing-value behaviour before using it in a real service.

Student lesson · 7 of 16

Find and repair a mistake

minutes = -1
if minutes < 0:
    label = "Invalid"
if minutes <= 12:
    label = "Short"
else:
    label = "Long"
print(label)

This faulty version prints Short. The second if starts a separate decision and overwrites Invalid. Its else belongs to that second if. Restoring elif makes the second test depend on the first test failing. Moving print inside one branch can also hide output on other paths; indentation affects behavior, not just appearance.

The script rejects negative integers, but it does not validate arbitrary types or check a measured duration. A supplied text value can raise an error during comparison. Keep the stated integer input contract and report the limitation honestly.
