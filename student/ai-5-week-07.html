Notice the evidence

Investigate the supplied Parameters and architecture case. Separate observations, given facts and assumptions before choosing an explanation.

Consider a dense network with 2 inputs, 3 hidden units using ReLU, and 1 output unit using identity. We call its widths 2 to 3 to 1. These widths, connectivity and activation choices describe its architecture.

The weights and biases supply the numerical values used by that architecture.

A fully connected hidden unit receiving 2 inputs needs 2 weights plus 1 bias. Three such units need 6 weights and 3 biases. The output receives 3 activations and needs 3 weights plus 1 bias. Total: 13 parameters.

Input values and computed activations are not additional parameters.

LayerWeightsBiasesTotal
2 inputs to 3 hidden units2 times 3 = 639
3 hidden values to 1 output3 times 1 = 314
Whole network9413

This counting rule assumes one separate bias per output unit and no shared or tied weights. Other architectures can use different rules.

Student lesson · 3 of 18

See how it works

Follow the mechanism for Parameters and architecture. Connect each labelled input, deciding step and result.

For a dense layer with n input components and m output units, each output has n weights and one bias. The count is n times m plus m, or (n + 1) times m. Count each layer separately before adding.

def dense_count(inputs, outputs):
    return inputs * outputs + outputs

print(dense_count(2, 3))   # 9
print(dense_count(3, 1))   # 4
print(dense_count(2, 3) + dense_count(3, 1))  # 13

The helper assumes positive integer widths and the bias convention stated above. It is a counting aid, not a model trainer. A ReLU has no fitted numerical parameters in this example.

Find and repair a mistake

Find the unsupported step in the Parameters and architecture claim and explain a repair using the supplied evidence.

Two networks can share an architecture and still make different predictions because their parameter values differ. Conversely, two architectures can happen to produce identical outputs on the few cases tested.

A count describes the model, not how well it has learned.

Check the claim against the facts

When comparing widths, keep the task, feature schema, training data, validation cases and evaluation rule fixed. Record the training budget and seed as well.

More parameters can increase flexibility, but they can also increase resource use and overfitting risk. Neither outcome follows from counting alone.

Recount the 2 to 3 to 1 model if every bias is omitted. State what the original count assumed.
