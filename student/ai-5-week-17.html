Student lesson · 3 of 16

See how it works

A pseudorandom generator produces a sequence determined by its state. In the same Python setup, recreating a local generator with the same seed and making the same calls reproduces the sequence below. Saving the generated values also removes ambiguity about which draw became which parameter.

from random import Random

def initial_values(seed):
    rng = Random(seed)
    return [rng.uniform(-1.0, 1.0) for _ in range(4)]

def train(v):
    states = [v]
    for _ in range(2):
        v = v - 0.1 * 5 * (v - 2)
        states.append(v)
    return states

first = initial_values(17)
second = initial_values(17)
assert first == second
print(first)
for start in [0.0, 1.0, 3.0]:
    print(start, train(start))

The four random numbers illustrate a saved initialisation sequence; they are not used in the three separate scalar training runs. The range [-1, 1] is a classroom choice, not a general recommendation for network initialisation. An extra random draw before assigning weights shifts which value is used, even if the seed stays the same.

All inputs and outcomes in this worked example are invented classroom data; no real model run is claimed.

Why this result follows

Initialisation supplies the parameter values before learning begins. The same update rule can follow different paths from different starts. Here the two paths end on opposite sides of two and have equal squared distance, so equal loss does not imply equal parameters. Save initial values and settings to reproduce this arithmetic, as well as the final result.

What this example does not establish

A saved seed alone does not reproduce every software or hardware execution; record environment and nondeterminism too.

Student lesson · 7 of 16

Find and repair a mistake

For the two-unit example, y = a ReLU(ux) + b ReLU(vx). At x = 1, u = v = a = b = 1, output is 2 and target is 1. Because both ReLUs are in their positive region, changing any one parameter slightly changes y at rate 1. Squared-error gradient is twice residual times that sensitivity, so each gradient is 2. Students can check it with the symmetric numerical probe from Week 10.

With identical initial weights, identical data and deterministic symmetric updates, these units remain copies and cannot learn distinct roles through those updates alone. Different hidden weights can break the symmetry. For example, u = 1 and v = -1 give hidden activations [1, 0] at x = 1 and [0, 1] at x = -1. This demonstrates different responses, not a guarantee of successful training.

Zero is not always an invalid start: v = 0 worked in our single trained-output-weight model. But setting all four weights to zero in the two-unit product model leaves every single-coordinate loss probe unchanged, because each path still contains a zero factor. Do not generalise the success of one scalar start to every architecture.

Locate the earliest unsupported step

Both runs use the same seed and generator. Run A assigns the first four draws to its weights. Run B draws a preview number first, then assigns the next four. Must the initial weight arrays match? What should be saved?

Show what you know

Save actual initial parameters, their order, data and split IDs, preprocessing rules, model formulas, loss convention, learning rate, batch order, update budget, selection policy, code version, software environment and final checkpoint. A seed helps replay one source of randomness; it does not specify all of these choices or guarantee identical results across different numerical environments.

Repeatability alone cannot prove correctness: a program can repeat the same mistake. Preserve hand-calculated checks as well as logs. When comparing starts, report every planned run instead of selecting a lucky result using final test outcomes. Next week locates shape and gradient errors.
