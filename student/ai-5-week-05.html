Main lesson · Section 2

Connect two named transformations in the right order

Both hidden units read the original input;the output reads their activations.

Complete hidden and output formulas

A network connects layers so that the output vector of one layer becomes the input vector of the next. Use a fictional numerical input x = [x1, x2].

The first layer computes z1 = x1 - x2 and z2 = x1 + x2 - 2, then applies ReLU separately: h1 = max(0, z1), h2 = max(0, z2). Its output is the ordered vector h = [h1, h2].

The next layer computes y = 2h1 - h2 + 1. It receives h, not the original x. It uses weights [2, -1] and bias 1, with identity as its output activation.

This is a two-layer computation when counting the layers with weights; an input placeholder is not counted here. All parameters are supplied, so this lesson performs no training.

Input/output sizes at each layer

First layer with ReLU2 components2 components
Output layer with identity2 components1 component

Distinguish parallel hidden units from the next layer

The two first-layer units both receive the same original x. They can be calculated in either order. Only after both activations are available do we evaluate the output layer.

    Runnable forward pass and its contract

    def forward(x):
    if len(x) != 2:
        raise ValueError("Expected two input components")
    x1, x2 = x
    z = [x1 - x2, x1 + x2 - 2]
    h = [max(0, value) for value in z]
    y = 2 * h[0] - h[1] + 1
    return z, h, y

print(forward([3, 1]))  # ([2, 2], [2, 2], 3)
print(forward([1, 3]))  # ([-2, 2], [0, 2], -1)

    The code assumes numeric inputs with the agreed meaning. Its length check does not validate units or field order. Python indices 0 and 1 correspond to the first and second hidden components.

    There is no feedback from y into h during this forward calculation.

    Main lesson · Section 7

    Find a shape or order bug before trusting the output

    Equal lengths do not guarantee matching meanings.

    Complete dimension,order and activation comparisons

    The output layer expects two inputs because its two weights match h1 and h2. If the hidden layer is redesigned to return three activations, the output layer needs a compatible three-input definition.

    Silently dropping an activation or inventing a third weight does not preserve the stated model.

    Order matters even when lengths match. For x = [4, 1], h = [3, 3] happens to be unchanged by swapping, so that case cannot reveal an order bug. For x = [3, 0], h = [3, 1] gives y = 6.

    Swapping only those hidden values gives 2 times 1 - 3 + 1 = 0. Swapping both the values and their matching weights would preserve the dot product.

    Keeping the output layer fixed, replacing ReLU with identity changes the model. For x = [1, 3], identity gives h = [-2, 2] and y = -5; ReLU gives h = [0, 2] and y = -1.

    More layers or a different activation do not establish better predictions without valid evaluation.

    Current explanation and response

    • The computed y is a numerical output, not a verified probability or a class by itself. If we separately declare class 1 when y >= 0 and class 0 otherwise, the worked inputs [3, 1] and [1, 3] receive classes 1 and 0.

      Their true labels are not supplied, so these calculations do not measure accuracy.

    • A hidden value is a computed feature. We should not name h1 as confidence or h2 as danger without evidence for that interpretation.

      Distinct inputs may also produce the same hidden vector: [0, 1] and [0, 2] both give h = [0, 0] and y = 1. A later deterministic layer seeing only h cannot recover the lost distinction.
