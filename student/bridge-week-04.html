Main lesson · Section 2

At most twelve minutes AND quiet

A time-only pass is different from full suitability.

Read the complete activity requirements

A fictional activity must take at most 12 minutes and be quiet. An activity taking exactly 12 minutes meets the time requirement. A quiet 15-minute activity does not.

Before writing code, underline each requirement and decide whether all requirements must hold or whether alternatives are allowed.

State input types and comparison syntax

Use a fresh conditions.py file with nonnegative integer minutes and an actual Boolean quiet flag. A comparison produces True or False for these values. The expression minutes <= 12 includes 12; minutes < 12 excludes it.

Use == for equality and != for inequality. A single = assigns a value to a name; it does not ask whether two values are equal.

    Reference · Boolean AND/OR/NOT truth table
    ABA and BA or B
    FalseFalseFalseFalse
    FalseTrueFalseTrue
    TrueFalseFalseTrue
    TrueTrueTrueTrue

    With Boolean operands, and needs both parts True. Inclusive or needs at least one True, so both True is allowed. not reverses a Boolean: not True is False and not False is True.

    Python can also apply and and or to other types; keep operands Boolean here so this table directly describes the result.

    Main lesson · Section 7

    Write both comparisons in an OR expression

    A bare second value is not a repeated equality check.

    Run the separate range/NOT/equality script

    minutes = 12
quiet = True
print((minutes >= 0) and (minutes <= 12))
print(not quiet)
print(minutes == 12)

    Compare correct and incomplete alternative checks

    This prints True, False and True. Parentheses make the two range checks clear. To express minutes equal to 8 or 12, write (minutes == 8) or (minutes == 12).

    Do not write minutes == 8 or 12: the number 12 is not a second equality comparison. Later lessons examine truth testing of other types.

    Keep supplied-input and permission limits

    The rule uses values supplied by a person. It does not verify that the activity is really quiet, and a True result grants no permission to act.

    Our input contract already assumes a valid integer and Boolean; handling wrong types is a separate task.
