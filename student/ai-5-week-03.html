Main lesson · Section 2

Add one bias after the weighted sum

The declared comparison turns an affine score into a toy class.

Compute the offset and name the equality rule

Use the fictional parcel schema [width in cm, height in cm]. Our model computes z = 2 times width - height - 3. The weights are [2, -1]; the bias b is -3. Compute the weighted sum first, then add the bias once.

The result is an affine score: a weighted sum plus a constant offset.

Now declare a classification rule: predict class 1 when z is at least 0, and class 0 when z is below 0. Equality belongs to class 1. These are invented categories for arithmetic practice, not a real parcel decision.

The weights and bias are supplied, so this is a forward calculation, not training.

Complete score and class examples

Input [width, height]Score zPrediction
[4, 2]8 - 2 - 3 = 31
[2, 4]4 - 4 - 3 = -30
[3, 3]6 - 3 - 3 = 01 at equality

Distinguish mathematical bias from unfair treatment

A bias is a mathematical parameter. It is not the same use of the word as unfair treatment; numerical offset alone does not establish whether a system is fair.

    Runnable score/class and numerical assumptions

    def classify(width, height, bias=-3):
    score = 2 * width - height + bias
    return score, int(score >= 0)

for height in [2, 3, 4]:
    print(classify(3, height))
# (1, 1), (0, 1), (-1, 0)

    The code assumes valid numerical measurements in the agreed units. Changing >= to > changes the equality case, even though the drawn line remains in the same place.

    Trace the same offset through two inputs

    Every score rises by the same amount even when only one prediction changes.

    Complete picture facts and formula contract

    Move a toy boundary with a bias while keeping its input weights fixed.

    Score z=2u-v-3; predict class 1 when z>=0. InputsA=[2, 1], B=[1, 1].

    All inputs and outcomes in this worked example are invented classroom data; no real model run is claimed.

    The picture uses the same formula z=2u−v+b with b=−3. A[2, 1]scores 0, class 1 at equality; B[1, 1]scores−2, class 0. Change only b to−1:both scores rise 2, A→2 and B→0, bothclass 1. The boundary changes from v=2u−3 to v=2u−1; its slope stays 2. The plotted parcel example uses width/height names for the same coordinate roles.

    The hand-chosen shift is a different supplied model, not a learned improvement or probability estimate.

    Trace original scores and included equality

    The bias adds the same offset after the input contributions. It moves the dividing line without changing the weights that set the line’s orientation. Class 1 includes score zero under our stated rule.

    That is why B changes class when the bias rises by two: its score moves from minus two onto the included boundary.

    Main lesson · Section 7

    Repair equality mistakes and automatic-improvement claims

    Moving a boundary does not by itself supply better labelled outcomes.

    Origin,valid measurement domain and fixed slope

    Without a bias, this score would be z = 2 times width - height and its zero line would pass through (0, 0). The offset lets the boundary move away from the origin.

    In this parcel schema zero dimensions are invalid measurements; the origin is still useful as a point on the extended mathematical graph.

    Changing bias from -3 to -1 increases every score by 2, but does not rotate the line. Changing a weight can rotate or otherwise change the boundary. Neither change is automatically an improvement.

    To compare models, retain labels, a declared metric, the same evaluation records and the separate training, validation and test roles.

    Test inclusive versus strict equality

    • At [3, 3], compare prediction under z >= 0 with prediction under z > 0. Does changing this comparison move the zero line?
