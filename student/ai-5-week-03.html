Student lesson · 2 of 17

Notice the evidence

Use the fictional parcel schema [width in cm, height in cm]. Our model computes z = 2 times width - height - 3. The weights are [2, -1]; the bias b is -3. Compute the weighted sum first, then add the bias once. The result is an affine score: a weighted sum plus a constant offset.

Now declare a classification rule: predict class 1 when z is at least 0, and class 0 when z is below 0. Equality belongs to class 1. These are invented categories for arithmetic practice, not a real parcel decision. The weights and bias are supplied, so this is a forward calculation, not training.

Input [width, height]Score zPrediction
[4, 2]8 - 2 - 3 = 31
[2, 4]4 - 4 - 3 = -30
[3, 3]6 - 3 - 3 = 01 at equality

A bias is a mathematical parameter. It is not the same use of the word as unfair treatment; numerical offset alone does not establish whether a system is fair.

Student lesson · 3 of 17

See how it works

Set z to zero to locate the boundary: 2 times width - height - 3 = 0, so height = 2 times width - 3. Plot width on the horizontal axis and height on the vertical axis. Boundary points include (2, 1), (3, 3) and (4, 5). Join them with a straight line and label the axes in cm.

At width 3, height 2 gives score 1 and class 1; height 3 gives score 0 and class 1; height 4 gives score -1 and class 0. Under this axis convention class 1 lies on or below the boundary. One point on each side checks that orientation.

def classify(width, height, bias=-3):
    score = 2 * width - height + bias
    return score, int(score >= 0)

for height in [2, 3, 4]:
    print(classify(3, height))
# (1, 1), (0, 1), (-1, 0)

The code assumes valid numerical measurements in the agreed units. Changing >= to > changes the equality case, even though the drawn line remains in the same place.

A pictorial worked case: Bias terms and decision boundaries

Move a toy boundary with a bias while keeping its input weights fixed.

The facts we will use

Score z=2u-v-3; predict class 1 when z>=0. InputsA=[2, 1], B=[1, 1].

All inputs and outcomes in this worked example are invented classroom data; no real model run is claimed.

Why this result follows

The bias adds the same offset after the input contributions. It moves the dividing line without changing the weights that set the line’s orientation. Class 1 includes score zero under our stated rule. That is why B changes class when the bias rises by two: its score moves from minus two onto the included boundary.

What this example does not establish

A linear boundary is a toy classifier rule. Raw score size does not automatically describe confidence or probability.

Student lesson · 7 of 17

Find and repair a mistake

Without a bias, this score would be z = 2 times width - height and its zero line would pass through (0, 0). The offset lets the boundary move away from the origin. In this parcel schema zero dimensions are invalid measurements; the origin is still useful as a point on the extended mathematical graph.

Changing bias from -3 to -1 increases every score by 2, but does not rotate the line. Changing a weight can rotate or otherwise change the boundary. Neither change is automatically an improvement. To compare models, retain labels, a declared metric, the same evaluation records and the separate training, validation and test roles.

Student lesson · 12 of 17

Show what you know

The boundary states what this particular formula predicts. It does not establish the true classes of all possible inputs. A point very far from the line need not have a reliable prediction when the model, features or data are inappropriate. The raw score is not calibrated confidence or a physical distance from the line.
