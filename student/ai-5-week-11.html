Student lesson · 2 of 17

Notice the evidence

Gradient descent uses new parameter = old parameter - learning rate times its gradient entry. The minus sign chooses the locally downhill direction for a positive learning rate. A negative gradient therefore increases the corresponding parameter.

Keep the Week 10 example: x = 2, target 3, y = 2w + b and L = (y - 3) squared. At [w, b] = [1, 0], the loss is 1 and gradient is [-4, -2]. With learning rate 0.1, new w = 1 - 0.1 times -4 = 1.4 and new b = 0 - 0.1 times -2 = 0.2.

QuantityBefore updateAfter update
Parameters [w, b][1, 0][1.4, 0.2]
Prediction23
Squared loss10

This particular step reaches zero loss on one example. It does not establish a unique parameter solution, successful learning on other examples or a generally ideal learning rate.

Student lesson · 3 of 17

See how it works

def step(w, b, rate):
    residual = 2 * w + b - 3
    dw, db = 4 * residual, 2 * residual
    new_w = w - rate * dw
    new_b = b - rate * db
    new_loss = (2 * new_w + new_b - 3) ** 2
    return new_w, new_b, new_loss

for rate in [0.0, 0.05, 0.1, 0.3]:
    print(rate, tuple(round(v, 6)
                      for v in step(1, 0, rate)))

A pictorial worked case: Updating parameters

Use one explicit gradient update and then recompute the loss.

The facts we will use

Model y=2w+b, target 5. Start w=1, b=1; learning rate 0.05. Initial y=3, error y−target=−2, squared loss 4.

All inputs and outcomes in this worked example are invented classroom data; no real model run is claimed.

Why this result follows

Gradient descent subtracts learning rate times gradient. A negative gradient makes this subtraction increase the parameter. Compute both gradients at the original [w,b] before updating either one. The small step brings the prediction closer to five, reducing squared error. A larger step can cross the target and undo that gain, so the new prediction and loss must be recalculated.

What this example does not establish

One successful toy update is not evidence of convergence for a real network or generalisation to unseen data.

Student lesson · 7 of 17

Find and repair a mistake

Suppose a program first changes w to 1.4, then recomputes the bias gradient using new w and old b. Its residual is now -0.2, so its bias gradient is -0.4 and new b becomes 0.04. Prediction becomes 2.84 and loss 0.0256. That is a different procedure from the declared simultaneous step, even though it also lowered this loss.

An excessive rate can increase loss. At rate 0.3, both coordinates move in the locally suggested direction but prediction jumps to 5 and loss rises from 1 to 4. Always evaluate and record the result. Later lessons compare learning-rate behaviour across repeated updates.

Student lesson · 12 of 17

Show what you know

A lower loss after a step supports progress on the objective and examples used for that step. It does not show that a model is safe, calibrated or better on unseen data. Keep the data split fixed and never use final-test labels to compute training gradients.
