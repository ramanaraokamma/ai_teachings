Main lesson · Section 2

Separate text syntax from the service contract

Reading a value is not accepting it for the task.

Understand the two decisions

JSON is text for exchanging values. Object keys and text values use double quotes; numbers are unquoted, and true, false and null are lowercase. Parsing converts the text into program values. Validation then checks the task’s expected fields, types and ranges. A parser can successfully read an array even when the task requires an object. Neither parsing nor schema validation proves that an observed count is true.

Read the activity-service task

A fictional activity service supplies JSON text. The input contract is a JSON object with name text and minutes an integer from 0 through 60. The output contract will be a record with accepted and minutes fields.

Parsing valid JSON is only the first step.

Main lesson · Section 3

Read the complete activity interface before running code

Closed fields, types, rejection output and policies

Current activity contract: exactly name and minutes. name is text with length greater than zero; this toy rule does not trim whitespace. minutes is an integer from 0 through 60; booleans and decimal-number values are rejected. No extra or duplicate fields are allowed. The output always has accepted and minutes; any rejection returns false and null.

Duplicate rejection is an explicit classroom policy; JSON libraries may otherwise retain a repeated name’s last value. Non-JSON NaN/Infinity constants are rejected. These checks are for short supplied classroom cards, not a production network parser.

Understand parsing before field access

JSON is a text format for exchanging values. Parsing asks whether the text follows that format. Schema checking asks whether the parsed value has the structure and values your task requires.

Start by checking that the whole value is an object, represented here by a Python dictionary. Only then look up name and minutes. A valid JSON list is still the wrong top-level structure for this contract.

Syntax success and acceptance are separate decisions.

Original one-record illustration · limitations retained
import json
text = '{"name": "Sketch", "minutes": 12}'
record = json.loads(text)
valid = (type(record) is dict
         and type(record.get("name")) is str
         and len(record["name"]) > 0
         and type(record.get("minutes")) is int
         and 0 <= record["minutes"] <= 60)
result = {"accepted": valid, "minutes": record.get("minutes")}
print(json.dumps(result))

The output is {"accepted": true, "minutes": 12}. JSON uses lowercase true, false and null; Python uses True, False and None. json.loads converts between representations.

The worked output line assumes the parsed top-level value is a dictionary; a robust interface must reject other top-level types before accessing fields.

    Complete validator and supplied cards

    import json

class DuplicateField(ValueError):
    pass

def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise DuplicateField('duplicate field')
        result[key] = value
    return result

def reject_constant(token):
    raise ValueError('non-JSON numeric constant')

def validate_activity(text):
    # This lesson supplies short text cards, not unbounded network input.
    rejected = {'accepted': False, 'minutes': None}
    try:
        record = json.loads(text, object_pairs_hook=unique_object,
                            parse_constant=reject_constant)
    except DuplicateField:
        return 'duplicate-field policy', rejected
    except (json.JSONDecodeError, ValueError):
        return 'syntax', rejected
    if type(record) is not dict:
        return 'schema: top-level object', rejected
    if set(record) != {'name', 'minutes'}:
        return 'schema: exact fields', rejected
    if type(record['name']) is not str or len(record['name']) == 0:
        return 'schema: name', rejected
    if type(record['minutes']) is not int:
        return 'schema: integer minutes', rejected
    if not 0 <= record['minutes'] <= 60:
        return 'schema: minutes range', rejected
    return 'accepted', {'accepted': True, 'minutes': record['minutes']}

cards = [
    '{"name":"Sketch","minutes":12}',
    '{name:"Sketch","minutes":12}',
    '[]',
    '{"name":"Sketch"}',
    '{"name":"Sketch","minutes":"12"}',
    '{"name":"Sketch","minutes":true}',
    '{"name":"Sketch","minutes":61}',
    '{"name":"Sketch","minutes":0}',
]
for number, text in enumerate(cards, 1):
    status, result = validate_activity(text)
    print(number, status, json.dumps(result, allow_nan=False))
