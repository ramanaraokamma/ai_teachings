Notice the evidence

Investigate the supplied Convolution as a local operation case. Separate observations, given facts and assumptions before choosing an explanation.

Use a fictional single-channel image with rows [1, 2, 0], [0, 1, 3] and [2, 0, 1]. Coordinates are zero-based row then column. Our kernel has rows [1, -1] and [0, 1].

At each position, multiply matching entries of a 2 by 2 window and the kernel, then add the four products. Use bias 0, stride 1 and no padding.

At the top-left window, the sum is 1 times 1 plus 2 times -1 plus 0 times 0 plus 1 times 1 = 0. Slide the same kernel right, then down. Only use windows that fit entirely inside the image; this is the valid boundary rule.

The feature map has rows [0, 5] and [-1, -1]. This neural-network convention keeps the kernel orientation fixed; mathematically it is cross-correlation. Mathematical convolution reverses the kernel along both spatial axes.

We use the fixed-orientation convention throughout, so every hand calculation and program agrees.

Student lesson · 3 of 18

See how it works

Follow the mechanism for Convolution as a local operation. Connect each labelled input, deciding step and result.

The following function assumes nonempty rectangular numeric arrays and a positive integer stride. It rejects a kernel larger than the image.

It computes one input channel, one output map, zero bias and no padding; no activation is applied inside the function.

def local_filter(image, kernel, stride=1):
    h, w = len(image), len(image[0])
    kh, kw = len(kernel), len(kernel[0])
    if kh > h or kw > w:
        raise ValueError("Kernel does not fit")
    out = []
    for r in range(0, h - kh + 1, stride):
        row = []
        for c in range(0, w - kw + 1, stride):
            value = sum(image[r+i][c+j] * kernel[i][j]
                        for i in range(kh) for j in range(kw))
            row.append(value)
        out.append(row)
    return out

x = [[1, 2, 0], [0, 1, 3], [2, 0, 1]]
k = [[1, -1], [0, 1]]
assert local_filter(x, k) == [[0, 5], [-1, -1]]
assert local_filter(x, k, 2) == [[0]]

The kernel weights are reused at all four positions. There are four kernel parameters, not sixteen separate weights. If we add one shared bias for this output map, there are five parameters.

The number of multiply operations grows with the number of windows even though the parameter count stays fixed.

Find and repair a mistake

Find the unsupported step in the Convolution as a local operation claim and explain a repair using the supplied evidence.

Check the claim against the facts

For no padding and a kernel that fits, output height is floor((H - Kh) / s) + 1 and width is floor((W - Kw) / s) + 1, where s is the positive integer stride. Floor means round down.

Count allowed start positions before using the formula. With a 3 by 3 image, 2 by 2 kernel and stride 2, the only row and column start is 0, so the output is 1 by 1.

Check the claim against the facts

Padding changes which windows exist and what they contain. Adding one border of zeros on every side changes this 3 by 3 input to 5 by 5. At stride 1 with our 2 by 2 kernel, output shape becomes 4 by 4.

Its top-left window is [[0, 0], [0, 1]] and its output is 1. Zero padding is a chosen boundary assumption, not a measured black region outside the picture.

If ReLU is applied after the unpadded sums, the feature map becomes [[0, 5], [0, 0]]. Negative responses are valid weighted sums before activation; they are not necessarily a software error.

Keep raw sums available when debugging so ReLU does not hide a mistake.

Show what you know

Use a genuinely new case for independent evidence. Previously discussed examples remain practice; use the separately named independent case before feedback.

These kernel weights were chosen for arithmetic practice, not fitted from data. A response of 5 is neither a probability nor proof that an object was recognised.

A trainable convolutional layer adjusts shared parameters using training examples. Additional channels require summing contributions across channels; that is beyond this single-channel calculation.

Sharing weights applies the same local rule at each allowed position. It does not guarantee that a whole image classifier ignores object location, especially when strides, boundaries or later layers change the result.

Next week studies pooling and the spatial information it can discard.
