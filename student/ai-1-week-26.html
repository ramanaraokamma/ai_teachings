Main lesson · Section 2

Write a contract for the fictional club card

Specify the audience, authorised source, required fields and missing-value rule.

Inspect what a vague request leaves open

“Write something good about our club” leaves many decisions unstated. Who will read it? Which facts may be used? What must the output contain? A more useful prompt states the job, audience, evidence and requirements.

This makes it easier to judge the result rather than choosing the answer that sounds most confident.

Read source C and the actual task

Use this fictional source C: the paper modelling club meets Monday in Room 7, and participants bring paper. C gives no start time. Our task is a short information card for Grade 6 readers.

It must report day, time, place and what to bring, using only C. There is no need to supply names or private information.

Read the complete P1 prompt

Prompt P1: Using only source C, produce an information card for Grade 6 readers. Return exactly four labelled lines in this order: Day, Time, Place, Bring. Copy or faithfully restate each supported value.

For a missing value write “not stated”. Add no other details. Source C: the paper modelling club meets Monday in Room 7; bring paper.

    Main lesson · Section 7

    Improve the specification without hiding failures

    Keep the scoring rule and tested conditions visible when comparing revisions.

    State what a few passing examples establish

    Suppose a revised prompt handles three classroom examples correctly. You can report that it passed those examples under the recorded conditions. You cannot conclude that it will always work.

    If outputs can vary between runs, plan repeated trials and keep every result. A single good response is not a reliability guarantee.

    Document prompt and criterion changes

    Use the failures to improve the specification and add revealing cases. Keep the same evaluation criteria when comparing versions; changing both the prompt and the scoring rule makes the comparison hard to interpret.

    A new requirement may justify a new criterion, but document that change rather than pretending the results used the same test.

    Repair both tempting claims

    • CLAIM A A perfect prompt can force a model to know missing facts.

    • CLAIM B Adding more words always makes a prompt better.

    Practise: score each criterion and preserve the log

    A failure may reflect noncompliance with an existing rule rather than a missing instruction.

    Record versions, inputs, outputs and checks

    A small test log can record prompt version, input case, output, each criterion’s result and the reason for failure. If you use an approved model, also record the model and available settings.

    Compare prompt versions on the same cases under the same recorded conditions. Keep all observed outputs rather than only the best-looking attempt.

    Distinguish an inadequate rule from a rule not followed

    P1 already tells the model not to invent missing values. A failed output can therefore be a failure to follow an adequate instruction, not necessarily a missing instruction.

    Inspect the actual output, retain the failure and try targeted changes if useful.
