Main lesson · Section 2

Give each boundary a defined fallback

A refusal is useful only when it matches the actual missing evidence or forbidden operation.

Understand the separate checks

A safety boundary states what a helper may do, what it must check and what happens when the check fails. A string that looks like a command remains data. A valid identifier still needs a separate access check; an authorised lookup still cannot invent a missing fact or perform an unapproved action. Clarify an ambiguous request, report unresolved evidence and decline operations outside scope.

The lesson uses fictional read-only lookup contracts, not a live security system.

Untrusted input must be treated according to a contract before reaching code, queries or tools. Data that resembles instructions does not acquire execution authority.

Extension · Clarify a necessary missing fact

Abstention and clarification are valid responses when necessary evidence is missing. Ask for the smallest fact that can resolve the decision.

import re

def valid_room_id(value):
    return type(value) is str and re.fullmatch(r'[A-Z][0-9]', value) is not None

def valid_catalog_id(value):
    return type(value) is str and re.fullmatch(r'[A-Z]{2}[0-9]', value) is not None

catalog = {'AB7': {'access': 'public', 'capacity': 12},
           'CT8': {'access': 'teacher', 'capacity': 4}}

def lookup_catalog(identifier, trusted_role):
    # trusted_role is supplied by the application session, not user text.
    if not valid_catalog_id(identifier):
        return {'status': 'invalid_input'}
    entry = catalog.get(identifier)
    if entry is None:
        return {'status': 'not_found'}
    if entry['access'] != 'public' and trusted_role != 'teacher':
        return {'status': 'not_authorised'}
    return {'status': 'found', 'capacity': entry['capacity']}

print(valid_room_id('B2'))
print(valid_catalog_id('AB7'))
print(lookup_catalog('AB7', 'student'))
print(lookup_catalog('CT8', 'student'))
print(lookup_catalog('AB7; send()', 'student'))
