Main lesson · Section 2

Keep the prefix and alternatives beside each probability

Weights need an explicit normalisation rule before they are probabilities.

The complete Status distribution

A constructed model uses prefix “Status:” and vocabulary alternatives ready, busy and unknown. Its next-token table is ready 0.5, busy 0.3, unknown 0.2. All entries are nonnegative and sum to 1.

A probability belongs to a token under this prefix and model, not to that token in every situation. An omitted vocabulary alternative would make the interpretation incomplete unless its probability were explicitly zero.

Detect an invalid distribution and normalise only permitted weights

A table containing 0.6,0.3,0.3 sums to 1.2 and is not already a probability distribution. If the values are nonnegative weights and the rule says normalise, divide each by 1.2. Do not silently treat weights as probabilities.

Negative weights cannot be repaired by this simple normalisation rule.

Representation extension · Token lookup and position scheme

Use a two-token vocabulary: ID 1 means red with embedding [1,0]; ID 2 means blue with embedding [0,1]. This lookup table is constructed, not trained.

The input red blue has embedding rows [1,0] and [0,1], so its shape is two sequence positions by two components. Reversing the text reverses the rows. ID 2 is not “twice as blue” as ID 1 is red.

A model needs a way to use order. A collection of vectors without any order-sensitive procedure may lose that distinction. We introduce one explicit toy scheme: add position vector [0,0] at position 0 and [2,0] at position 1.

These invented values teach arithmetic; they are not a recommended production encoding.

Main lesson · Section 6

Challenge greedy decoding, then trace a separate sun/rain tree

Keep Status, A/B and sun/rain distributions separate.

Read the complete A/B counterexample

Greedy decoding chooses the largest next-token probability at each step, with an explicit tie rule if needed. It does not always maximise the probability of a complete sequence. Counterexample: first-step A=0.6 and B=0.4.

Given A, end=0.51 and x=0.49; given B, end=1. Greedy produces A,end with probability 0.306. The path B,end has probability 0.4, larger than 0.306.

This comparison concerns exactly two-step paths; longer completion probabilities require the later conditionals too.

Separate path likelihood from factual support

A high path probability measures the model’s preference over these specified paths. It is not evidence that a status claim matches a live observation. Format checks and source checks remain separate.

Read the separate pictured sun/rain branches

A fictional two-stage token tree illustrates next-token prediction.

First token probabilities: sun 0.55, rain 0.45. Given sun: end 0.4, more 0.6. Given rain: end 0.9, more 0.1.

These are complete toy branches; end paths stop, more paths do not.

Trace all four branch products

Conditional probabilities describe what follows a particular prefix. Multiplying along a path gives its joint probability.

The four branch products sum to 1, but the two end paths sum to 0.625 because more branches have not ended. Greedy decoding selects sun then more; it does not guarantee the most likely complete sequence.

Representation extension · Row sum loses order

The elementwise sum of the represented rows is [3,1] for both red blue and blue red. This aggregate loses the row-order distinction despite the position additions.

A later computation must actually use the represented rows appropriately; merely adding position vectors does not guarantee that every summary preserves order.

A position scheme may use learned values or a deterministic construction. The original Transformer added positional information to embeddings. Modern architectures can use other order-sensitive schemes.

Our two-vector example demonstrates one possible mechanism and one information-loss failure, not all architecture choices.

      from fractions import Fraction as F
first = {'ready':F(1,2), 'busy':F(3,10), 'unknown':F(1,5)}
end_given = {'ready':F(4,5), 'busy':F(1,2), 'unknown':F(1)}
assert sum(first.values()) == 1
paths = {}
for token, probability in first.items():
    paths[(token,'end')] = probability * end_given[token]
    paths[(token,'today')] = probability * (1-end_given[token])
print(paths)
print('all paths:',sum(paths.values()))
print('end paths:',sum(p for (token,next_token),p in paths.items() if next_token=='end'))
# Separate sun/rain tree: more branches are unfinished, not missing mass.
weather = {'sun':F(55,100),'rain':F(45,100)}
weather_end = {'sun':F(4,10),'rain':F(9,10)}
ends = {token:probability*weather_end[token] for token,probability in weather.items()}
print('sun/rain ends:',ends,'total:',sum(ends.values()))
