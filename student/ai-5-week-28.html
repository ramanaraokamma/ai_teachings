Main lesson · Section 2

Separate the frozen extractor from the fitted head

Our supplied extractor demonstrates reuse mechanics; it has no source-training history.

Transfer learning and the transparent stand-in

A source model may learn useful features before we have many labels for a new target task. Transfer learning reuses those learned features or parameters. One approach freezes the feature extractor and fits a new output head.

Fine tuning instead updates some or all of the reused parameters, usually together with the head.

Use a transparent stand-in for a source-trained extractor: f(x) = ReLU(x1 + x2), with supplied weights [1, 1] and bias 0. ReLU keeps a positive value and replaces a negative value with zero.

Here x1 and x2 are nonnegative fictional event counts, so f(x) is their sum. We did not train this extractor on a source dataset; this exercise demonstrates the mechanics of reuse, not measured transfer benefits.

Training tie rule and baseline rule

The tie rule prefers the smaller threshold if training mistake counts match; there is no tie here. The extractor remains unchanged. The code assumes finite numeric counts and valid binary labels.

A constant baseline predicts the most frequent training label; with two of each, our declared tie rule chooses 0.

Run the complete fit and validation audit

"""Supplied frozen extractor; fit only the target threshold on training rows."""
from math import isfinite
train = [('T1', [1, 1], 0), ('T2', [1, 3], 0),
         ('T3', [4, 2], 1), ('T4', [5, 3], 1)]
validation = [('V1', [2, 1], 0), ('V2', [3, 4], 1)]
def feature(x):
    if len(x) != 2 or any(not isfinite(v) or v < 0 for v in x):
        raise ValueError('Need two finite nonnegative counts')
    return max(0, x[0] + x[1])
def predict(x, threshold):
    return int(feature(x) >= threshold)
def errors(threshold):
    return sum(predict(x, threshold) != y for _, x, y in train)
candidates = [3, 5, 7]
best = min(candidates, key=lambda t: (errors(t), t))
counts = {y: sum(label == y for _, _, label in train) for y in (0, 1)}
baseline = min(counts, key=lambda y: (-counts[y], y))
ledger = [(name, feature(x), y, predict(x, best), baseline)
          for name, x, y in validation]
head_correct = sum(pred == y for _, _, y, pred, _ in ledger)
baseline_correct = sum(base == y for _, _, y, _, base in ledger)
assert [errors(t) for t in candidates] == [1, 0, 1]
assert (best, baseline, head_correct, baseline_correct) == (5, 0, 2, 1)
assert predict([2, 3], best) == 1  # equality belongs to class 1
print('Threshold mistakes:', [(t, errors(t)) for t in candidates])
print('Training label counts:', counts, 'baseline:', baseline)
print('Validation: name, h, label, head, baseline', ledger)
print('Correct on same two rows:', head_correct, baseline_correct)
# Different target: first count exceeds second. Both original features collide.
u, v = [1, 3], [3, 1]
assert feature(u) == feature(v) == 4
# This repair is hand supplied, not trained or independently evaluated.
def supplied_repair(x):
    return int(max(0, x[0] - x[1]) >= 1)
assert (supplied_repair(u), supplied_repair(v)) == (0, 1)
print('Collision h:', feature(u), feature(v), 'supplied repair:',
      supplied_repair(u), supplied_repair(v))

    Main lesson · Section 7

    Check whether the frozen representation keeps the needed distinction

    A better head cannot recover information that the feature already discarded.

    Reason about a changed target

    Now change the target: predict 1 when the first count is greater than the second, otherwise 0. U [1, 3] has label 0 and V [3, 1] has label 1, but both become h = 4.

    Every fixed deterministic head receiving only this h must give both the same prediction. At least one of the two will be wrong, regardless of how many extra head parameters we add.

    Fine tuning could change the extractor to retain relevant distinctions; it does not guarantee success. To see a possible change, hand-set the weights to [1, -1], keep bias 0 and use threshold 1.

    U then gives ReLU(-2) = 0 and predicts 0; V gives ReLU(2) = 2 and predicts 1. This hand-chosen repair is not a trained result or an independent evaluation.

    Keeping the original input alongside h is another possible representation change. Any such change needs a new training and evaluation plan.

    Normalising the inputs also changes the pipeline; last week showed why that can remove useful magnitude information.
