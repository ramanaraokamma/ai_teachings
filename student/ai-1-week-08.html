Main lesson · Section 2

Define the task before choosing features

The delivery task uses two inclusive size limits under a declared paper convention.

Read the full card task

Imagine a paper sorting task for a model delivery station. Each rectangular card has a length, width, colour and card number.

The station labels a card fits if its length is at most 12 centimetres and its width is at most 8 centimetres. Both limits include equality.

Cards stay flat in the marked orientation; turning, bending and thickness are outside this paper task. All measurements in the first examples are known positive whole numbers.

Separate features, identifiers and the target

A feature is a recorded input property, such as width in centimetres. The target label is the answer we want to produce: fits or too large under this guide. Decide what the answer means before choosing the inputs.

A card number can help us find a record, but knowing its number does not tell us its dimensions.

Recognise when a direct rule is sufficient

This guide already gives us a direct rule, so we do not need to train a model to solve it. We use the task to investigate the information that either a rule or a learned model would need.

Later, when relationships are learned from examples, the same question remains: did we supply the distinctions the task requires?

Inspect the candidate inputs

  • State the label rule and the fixed orientation. Which recorded properties decide the label? Which property only identifies a card, and what information would not yet exist before inspection?

Main lesson · Section 3

The same feature record can hide different answers

Keep the necessary dimensions, their order and their units.

Read the two cards

Card A is 10 centimetres long and 7 centimetres wide. Card B is 10 centimetres long and 9 centimetres wide. A fits; B is too large because its width exceeds 8. Compare two ways of recording these cards.

Compare short and fuller records

Explain what the missing width prevents

A system receiving only the length cannot use the hidden width to tell these two cards apart. The same input, 10, is paired with two different correct answers.

It may guess, return an uncertainty, or use a usual answer, but length alone cannot guarantee the right label for both. A more complicated model cannot reconstruct this missing distinction with certainty from that input alone.

State the feature convention

A feature record needs a consistent order and units. Here we write length in centimetres first, then width in centimetres.

The record 10, 7 means something different if someone silently switches the order or records millimetres. Write the definitions alongside the data.

That is a statement about our task, not a claim that colour is useless for every task. For sorting red and blue cards, colour would be essential.

Main lesson · Section 7

Test the representation before trusting a practice score

Identical inputs can conceal different targets, and a changed task may need different inputs.

Use a two-answer counterexample

Before adopting a feature set, state the task, name the inputs with units, and ask whether two different answers can share the same input record. Construct such a pair if you can.

Then check that each input is available at the time the answer is needed. These checks can reveal a broken representation before any model is trained.

Respect the paper-task assumptions

For our known measurements and fixed orientation, length and width are sufficient to apply the paper rule exactly.

That does not establish whether a real parcel will fit through a real opening: thickness, shape and measurement error were excluded. If the task changes, review the features again.

More columns are not automatically better; each one needs a reason to be collected and used.

Main lesson · Section 8

Draw the line at decision time

The answer sticker is useful for teaching or checking, but it is unavailable for this earlier decision.

Find the leaked target

After measuring a card, a teacher adds a sticker saying fits or too large. A learner proposes using sticker text as an input to predict the label before that inspection.

The sticker seems excellent in the completed records because it contains the answer. But it does not exist at the time of the intended prediction. This is leakage: development has used information the real task cannot provide.

Draw a line at the moment the system must answer. On the before side, put the permitted measurements available then. On the after side, put the final label sticker.

Keep labels available for teaching and checking predictions, but do not feed the sticker back in as an input for this task.
