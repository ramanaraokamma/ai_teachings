The table shape is 6 by 2: six vocabulary entries and embedding dimension 2. The ID sequence [2, 4, 0, 0] becomes [[2, 0], [0, 2], [0, 0], [0, 0]], with shape 4 by 2. Its mask remains [1, 1, 0, 0].

Keep the real-position mask in a vector average

UNK is a real position when it replaces an unknown symbol, so its vector is not automatically excluded.

    Calculate every matching-coordinate difference and retain all ties

    Nearest means nearest under this table,metric and candidate set.

    Complete squared-distance definition

    Use squared Euclidean distance: square each component difference and add. From GO [2, 0] to TURN [1, 1], the distance is (2 - 1) squared + (0 - 1) squared = 2. To STOP it is 8; to WAIT it is 5.

    TURN is therefore the nearest of those three under this table and metric.

    Candidate,precision and finite-input contract

    For a named-token query GO, exclude GO itself as well as reserved PAD/UNKroles. For the arbitrary query[1, 0], use all four regular candidates; it is not a named token in the table. nearest returns every exact nearest tie, sorted only for display. These integer coordinates make exact ties checkable; other numerical experiments need a declared precision policy.

    The functions check nonempty/equal dimensions and nonempty candidates but assume finite numeric components. All coordinates in this original table were hand-chosen.

    The candidate set excludes PAD, UNK and the query token itself. Otherwise a query would normally retrieve itself at distance zero.

    This code assumes finite numeric components and uses exact ties, appropriate for these integer examples. Floating-point comparisons in other experiments need a declared precision policy.

known = {"GO": 2, "TURN": 3, "STOP": 4, "WAIT": 5}

def distance2(a, b):
    if len(a) != len(b) or not a:
        raise ValueError("Need equal nonempty dimensions")
    return sum((x - y)**2 for x, y in zip(a, b))

def nearest(query, candidates):
    if not candidates:
        raise ValueError("Need candidates")
    scores = {name: distance2(query, vector)
              for name, vector in candidates.items()}
    best = min(scores.values())
    return sorted(name for name, d in scores.items() if d == best)

    Main lesson · Section 7

    Separate an adjustable table row from a justified meaning claim

    Keep the original lookup table and isolated updated copy as different versions.

    Complete isolated objective and its limited conclusion

    An embedding table can be trainable: an optimisation procedure adjusts its entries to reduce a declared objective.

    To isolate one update, let the GO row e start at [2, 0] and use the classroom loss J(e) = (e1 - 0) squared + (e2 - 2) squared.

    The target vector [0, 2] is chosen for this arithmetic demonstration, not discovered evidence about the word GO.

    The gradient at the start is [4, -4]. With learning rate 0.25, subtract the step to obtain e = [1, 1]. Loss decreases from 8 to 2. Keep every other table row frozen in this isolated example.

    GO now has the same vector as TURN, so a downstream rule receiving only this vector cannot distinguish those two tokens.

    This update proves only that the declared objective decreased. It does not prove that the new neighbourhood reflects useful meaning. Learned neighbourhoods depend on the training data, objective and model.

    A nearby token need not be a safe substitute, have the same label, or be interchangeable in a sentence or command.

def lookup(ids):
    if any(type(i) is not int or not 0 <= i < len(table) for i in ids):
        raise ValueError('Token ID is outside this saved vocabulary')
    return [table[i][:] for i in ids]

def masked_vector_mean(vectors,mask):
    if not vectors or len(vectors)!=len(mask) or any(m not in (0,1) for m in mask):
        raise ValueError('Need aligned vectors and binary mask')
    width=len(vectors[0])
    if width==0 or any(len(v)!=width for v in vectors):
        raise ValueError('Need consistent nonempty vector dimensions')
    count=sum(mask)
    if count==0:
        raise ValueError('No real vectors')
    return [sum(v[j] for v,m in zip(vectors,mask) if m)/count for j in range(width)]

    04. Change one thing. Trace what follows.

    Original case: P is nearest under the declared metric; this is a geometric result, not proof of meaning. Changed condition: Move the query to [2, 1].

    Expected result: Q becomes nearest with squared distance 1; P distance 4; R distance 10. Reason: Changing the query position changes geometric neighbours while the stored table remains fixed.

    Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

    05. Connect the explanation to its limit

    An embedding stores each item as an ordered vector. Under squared Euclidean distance, subtract matching coordinates, square their differences and add. The smallest total identifies the nearest supplied vector.

    These invented coordinates let us check geometry exactly; a claim that neighbours share meaning needs evidence about how the representation was learned and used.

    Limit: Embedding geometry depends on training, metric and scale; proximity does not prove truth, causation or source permission.

    Explain the case, then point to a limit on the claim.
