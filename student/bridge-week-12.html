    Read the complete tiny contract and test scope

    Use a test that catches the boundary bug. A function should classify an integer as tiny exactly when it is less than three.

    Python 3 intended function: return x<3. Test cases: (2,True),(3,False),(4,False). Candidate bug: return x<=3.

    The complete tiny program below uses assertions in normal test execution. Correct <3 passes 2,3,4 and prints the completion line. Changing only < to <= passes the first assertion, fails at 3 with AssertionError and never runs the assertion for 4 or final print. The graphic compares expression results one at a time; it is not a trace claiming later assertions executed after failure.

    The completion message is a literal string, not an automatic count of executed checks. If removing a test, relabel it for the two retained checks. These are local test checks, not a production input-validation mechanism.

    Trace the deciding boundary

    A revealing test distinguishes a correct implementation from a plausible mistake. Checking only values far from the boundary would miss this inclusive-versus-strict bug.
