Main lesson · Section 2

Turn a suspicious input into a reproducible test

A test needs scope, expected behavior and an inspectable result.

Understand bounded adversarial testing

Red teaming deliberately probes a defined failure boundary so it can be repaired. Start with a permitted toy fixture and a specific expected behavior. A final refusal is only one part of the result: the system may already have attempted an unauthorised action or exposed data. Conversely, a blocked proposal is not evidence that an external operation executed.

This lesson uses complete fictional paper traces; no real uploads, email, accounts or private records are involved.

Red-team exercises probe explicit failure boundaries in an authorised isolated fixture environment. Their purpose is evidence-based improvement.

Extension · Lower-authority source instructions

Prompt injection places instruction-like text in a lower-authority source such as a retrieved document. The application must preserve its original authority boundaries.
