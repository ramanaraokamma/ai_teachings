The hidden-target game and worst-case rule

Imagine one hidden target among eight fictional catalogue cards. All eight are still possible. A truthful yes/no answer lets you keep only cards matching that answer. This is a stated identification-game criterion, not a training-error or probability calculation.

A closer explanation

A decision tree asks a feature question and follows a branch to a prediction. A tree with one question has depth one and is sometimes called a stump. This retained Week 14 review fits a question and its leaf predictions from training labels. The main Week 15 guessing-game task instead compares the largest group of remaining possible target cards.

Predict before executing the complete audit

cards = [("M1", "mystery", "paperback", "English"),
         ("M2", "mystery", "paperback", "English"),
         ("M3", "mystery", "paperback", "English"),
         ("M4", "mystery", "hardback", "English"),
         ("S1", "science", "paperback", "English"),
         ("S2", "science", "paperback", "English"),
         ("S3", "science", "paperback", "English"),
         ("S4", "science", "hardback", "English")]
questions = [("mystery?", 1, "mystery"),
             ("paperback?", 2, "paperback"),
             ("English?", 3, "English")]
def audit(possibilities):
    best = None
    best_worst = len(possibilities) + 1
    for name, column, value in questions:
        yes = sum(card[column] == value for card in possibilities)
        no = len(possibilities) - yes
        worst = max(yes, no)
        print(name, yes, no, worst)
        if worst < best_worst:
            best, best_worst = name, worst
    return best
print("chosen", audit(cards))
remaining = [card for card in cards if card[1] == "mystery"]
print("after mystery Yes", audit(remaining))

Understand the count and candidate comparison

The tuple fields are ID0, subject1, binding2, language3. Each question stores its name, field position and wanted value. Equality gives True for a Yes card and False for a No card; sum counts True as1 and False as0. no is the remaining count and max chooses the larger branch. The strict < keeps the first candidate when scores tie. The final list comprehension keeps the four mystery cards before recounting. The audit assumes a nonempty possibility set with these complete, trusted fields.

Interpret the original and changed-set results

For all eight cards the question rows print mystery?4 4 4; paperback?6 2 6; English?8 0 8, then chosen mystery?. After a truthful Yes to mystery?, the four remaining cards give mystery?4 0 4; paperback?3 1 3; English?4 0 4, then after mystery Yes paperback?. That second comparison uses the explicitly supplied joint table, not just the original marginal totals.

Week 14 review · Earlier fitted-tree program
rows = [(1, 0, "blocked"), (1, 1, "blocked"),
        (1, 0, "blocked"), (0, 1, "clear"),
        (0, 0, "clear"), (0, 1, "blocked")]
def majority(labels):
    if labels.count("blocked") > labels.count("clear"):
        return "blocked"
    return "clear"
best_errors = len(rows) + 1
for feature in [0, 1]:
    leaves = {}
    for value in [0, 1]:
        labels = [row[2] for row in rows
                  if row[feature] == value]
        leaves[value] = majority(labels)
    errors = 0
    for row in rows:
        if leaves[row[feature]] != row[2]:
            errors = errors + 1
    print(feature, errors)
    if errors < best_errors:
        best_errors = errors
        tree = (feature, leaves)
print(tree[0], tree[1][0], tree[1][1])

Feature 0 is near; feature 1 is tall; row[2] is the label. Output is 0 1, then 1 2, then 0 clear blocked. Near makes one training mistake: near=0 contains two clear labels and one blocked, so that leaf predicts clear.

Near=1 contains three blocked labels. Tall makes two mistakes because both its groups have a blocked majority.

The stored tree contains the chosen feature and its two learned leaves. The code assumes nonempty data, binary flags, allowed labels and examples on both branches of each candidate.

An empty branch would need a declared fallback; this small example does not implement one. The score is total training mistakes, not an average giving small and large branches equal weight.

This is an explicitly limited depth-one learner. General tree algorithms can repeat split selection within branches and often use impurity criteria such as Gini. Our code does not implement that full procedure.

Keeping the scope small lets you inspect every decision.

Keep the criterion and its limits visible

Balanced possibilities and low classification error are different goals.

What the branch counts establish

A 4/4 split leaves at most4; a6/2 split can leave6, and an8/0 split cannot narrow the original eight cards. This ranking answers a worst-case count question. It does not show that the answer is truthful, the tags are accurate, the question is equally cheap to ask, or the expected number of later questions is minimal. A different probability or cost model needs an explicitly different calculation.

Choose recommender questions for a declared purpose

Do not silently turn multiple acceptable books into one hidden target.

This week’s practical portfolio contribution

For an invented reader and catalogue, state the purpose of a question before ranking it. In a hidden-target game, minimise the largest possible remaining set. In a recommender, a reader may accept several subjects or not know a preference; truthful answers need not identify one hidden book. Declare allowed answers and review handling, avoid unnecessary personal questions, and record why the chosen question helps the actual task. Do not claim a worst-case split guarantees satisfaction.

Choose recommender questions that distinguish feasible options, documenting the decision criterion rather than asking unnecessary personal details.
