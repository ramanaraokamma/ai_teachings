Explain the mechanism

Explain the mechanism

Follow the information instead of imagining magic inside the machine.

INPUT light measured at grid locations

PROCESS store and transform pixel values

OUTPUT a displayed, resized, blurred, or classified image

CORE IDEA A digital image is a grid of measured color values.

UNDER THE HOOD Digital images sample a scene across a spatial grid. Each pixel stores channel values, commonly red, green, and blue. Resolution controls sampling density; transformations operate on numbers, not on an intact object inside the computer.

Draw a fresh example with all three stages:

Every step connects a claim to observable evidence.

CASE A 5 by 5 black-and-white picture can be stored as 25 numbers, one value for each pixel position.

STEP 1 — OBSERVE light measured at grid locations

STEP 2 — TRACE store and transform pixel values

STEP 3 — CONCLUDE a displayed, resized, blurred, or classified image

MODEL REASONING Each grid position becomes one displayed square. A blur combines nearby values, so isolated corners and thin lines disappear before large regions. The computer transforms numbers; the human viewer recognizes the shape.

DO NOT OVERCLAIM A pixel is a measurement at a location, not a tiny copy of the object.

What new evidence could change this answer?

Concrete teaching case

A 2 by 2 image has rows [0,1] and [1,0]. Zero means white and one means black.

Draw it, then change the top-left value to 1.

Exact explanation to model

Initially top-right and bottom-left are black. The change produces three black squares. Pixel values encode an image; object recognition is a separate interpretation.

Explain the added worked example

Imagine sending a small black-and-white sign using only numbers. We can divide the sign into a grid, record 1 for a black square and 0 for a white square, and read each row from left to right, starting at the top. The receiver needs the width, height and these conventions to reconstruct the same arrangement.

A pixel is a position with a recorded value. In our simplified binary image, one value selects black or white. Other image formats can record brightness levels or multiple colour channels. The convention 1 means black belongs to this exercise; it is not a universal rule for every digital image.

Encoding a picture does not recognise what it depicts. A program can store or display the numbers without calling the image a letter, an arrow or a person. Interpretation is another operation, just as displaying a book title was different from reading the entire book in Week 2.

The first row is 0,1,0, so only its middle pixel is black. The second row is 1,1,1, so all three are black. The third row repeats the first. This reconstructs the displayed cross-like pattern under our convention.

A flattened record would be 0,1,0,1,1,1,0,1,0. Without the grid dimensions, the same nine values could also be drawn in one row of nine. Keep the shape information with the values. Width times height counts pixels; it does not tell us their contents.

The second arrangement fills the top row and two positions below it. Both have five black pixels and nine pixels in total, yet they are different images.

A pictorial worked case: Pictures Become Numbers

Two fictional 2-by-3 pixel badges contain the same number of dark squares.

The facts we will use

Dark=1, light=0; rows are read top to bottom, left to right.

Badge A rows: 1,0,1 / 0,1,0. Badge B: 1,1,1 / 0,0,0.

Why this result follows

A grid preserves where each brightness belongs. Adding the six values preserves only the dark count, which is 3 in both images. The total therefore cannot distinguish these badges. Dimensions and reading order belong to the representation, not to an optional caption.

What this example does not establish

This toy binary encoding does not include real photographs’ colour channels, compression or illumination effects.

Change one thing in the pictured case

Change: Change A’s bottom-left pixel from 0 to 1.

Prediction: A now has four dark pixels; its row encoding is 101 / 110.

Reason: Exactly one light pixel becomes dark; the other five positions remain unchanged.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Demonstrate and guide practice

Demonstrate and guide practice

Board sequence

Write the given facts: A 2 by 2 image has rows [0,1] and [1,0]. Zero means white and one means black.

Write the question to explain: Draw it, then change the top-left value to 1.

Reveal after predictions: Initially top-right and bottom-left are black. The change produces three black squares. Pixel values encode an image; object recognition is a separate interpretation.

Keep for an independent attempt: Use 0 for dark and 1 for light. Draw a two-by-two image with rows [1,0] and [0,1]. Then change only the bottom-left pixel to light. Which number changes?

Classroom dialogue

Ask: Which facts are given, and which would we have to assume? Learners mark relevant details before discussing answers.

Say: Predict first. Show the rule, information path or calculation that would produce the result. A correct guess is not yet an explanation.

Reveal reasoning one step at a time. Explain why a tempting alternative fails. Write units and denominators for arithmetic, trace conditions for decisions, and identify supporting sources for claims.

In pairs, one learner solves while the other checks evidence; exchange roles. Remove the worked answer before independent assessment.

Model these guided questions

The two rows are black-white-black and white-black-white, giving three black pixels. Other arrangements share that count, so it cannot recover positions. For the exit, move one black pixel to a previously white position while preserving the total; the image changes but the count does not.

Diagnose and reteach

CLAIM TO REPAIR An image is stored as its object name.

For guessing, return to given facts and request a trace. For vocabulary without application, use one example and one non-example. For arithmetic errors, check the setup before the calculation. Finish with a different uncoached case before recording mastery.

Address these additional misconceptions

The number one always means black: Our convention states that meaning. Other encodings use different scales or channels; read their specification.

A pixel count is the picture: Have students reconstruct two different arrangements with the same count.

Storing pixels recognises the object: A grid decoder only reconstructs the representation. A separate interpretation step assigns a category.

Worked case answer

Independent question

Use 0 for dark and 1 for light. Draw a two-by-two image with rows [1,0] and [0,1]. Then change only the bottom-left pixel to light. Which number changes?

Expected independent answer

The original light pixels are top-left and bottom-right. The bottom-left entry changes from 0 to 1, giving rows [1,0] and [1,1]. Position and value both matter.

Original transfer answer

Row-major encoding is [1,0,1,0,1,0], with shape 2×3. Interpreting the same list column-first gives top [1,1,1] and bottom [0,0,0]. Values need shape and ordering conventions; encoding alone does not recognise an object.

Explanations for the additional workbook examples

W1 Read and reconstruct

Using 1 for black and 0 for white, draw width 3, height 2 with rows 1,0,1 and 0,1,0. Read it back into numbers and count black pixels.

The upper row has black, white, black; the lower row has white, black, white. Reading back gives the supplied two rows. There are three black pixels among six total positions.

W2 Preserve the missing field

A message contains 1,0,0,1,1,0 but gives no dimensions. Show a one-row arrangement and a two-row arrangement using the same values. Name the extra information that would distinguish them.

One row of width 6 is [1,0,0,1,1,0]. Two rows of width 3 are [1,0,0] and [1,1,0]. Specify width and height, plus reading order and colour convention. The values alone do not choose the shape.

W3 Test a count feature

A classifier receives only the number of black pixels. Can it always distinguish the chapter's cross from every other three by three pattern? Construct a different pattern with the same count and explain.

No. Rows [1,1,1], [1,1,0], [0,0,0] have five black pixels, as does the cross, but a different arrangement. The classifier receives identical input counts for the two, so that feature alone cannot distinguish them.

W4 Design a new counterexample

Create two different images of width 4 and height 2, each with exactly three black pixels. Write both complete row encodings. Explain which fact their shared count retains and which difference it discards.

One valid pair is A [1,1,1,0]/[0,0,0,0] and B [1,0,0,0]/[0,1,0,1]. Both have two rows of four values and three ones. Count retains the number of black positions but discards their locations. Other valid pairs are accepted if dimensions, counts and arrangements meet the constraints.

W5 Locate an input problem

A program receives the correct grid but displays black wherever the code says 0 and white wherever it says 1. A student proposes collecting more classifier examples. Identify the earlier mismatch and the first check to perform.

The display uses the opposite colour convention from the sender. Check and align the encoding/decoding convention, then reconstruct a known grid. More classifier examples would not be the first repair for this identified input/display mismatch.

Support and fresh reassessment

Provide large tactile or printed cells, with numbers as well as shading so colour is unnecessary. Let learners dictate row values. Extension: construct two grids with equal counts in every row but different arrangements, showing that row totals still lose information.

Use feedback, labs and repair paths

Use the two formative questions as supported practice, not as independent mastery scores. Discuss the deciding evidence rather than accepting a guessed selection.

The feedback comes from the reviewed public worked case. Do not reveal the separately reserved independent teacher answer until the learner has attempted that case.

Ask students to predict before running code. Preserve errors and actual outputs; collect a changed test and an explanation. The branch-boundary and indexing lessons deliberately include failure cases.

Use the earlier worked-explanation links to address a specific missing building block, then return to the current question. Adapt this suggestion after observing the learner; it is not an automatic diagnosis.

Collect the completed-work portfolio as evidence. Record support separately from correctness, and assess explanation, trace/test and limitations. Progress ticks and quiz selections alone do not establish mastery.
