Explain the added worked example

Explain the added worked example · 1

A complete process says what happens for every kind of request in the task. It must handle a fitting activity, no fitting activity and unusable input. We will design a paper algorithm before building the prototype.

Its decisions use the requirements from Week 30, so a different drawing should not silently change what counts as correct.

Explain the added worked example · 2

Keep the same catalogue order: B1 Bookmark drawing, 10 minutes, quiet Yes; B2 Story circle, 8 minutes, quiet No; B3 Pattern puzzle, 12 minutes, quiet Yes; B4 Tower challenge, 15 minutes, quiet No.

These are fixed paper-model values with materials assumed available. Valid input is a whole number of minutes from 0 to 30 and Quiet required Yes or No.

Explain the added worked example · 3

A candidate fits when its required minutes are no more than the available minutes and either quiet is not required or the activity is quiet. Both parts must hold.

The output is the first fitting activity in catalogue order, with a reason, or a clear no-match result. Invalid or missing input produces a clarification request. None of these outputs books materials or publishes a message.

Explain the added worked example · 4

Begin by checking the request. If minutes are missing, outside 0 to 30 or not a whole number, ask for a whole number in that range. If the quiet field is not Yes or No, ask for one of those values.

State the fields needing correction and stop this run. When a corrected request arrives, validate it as a new run rather than continuing with old candidate state.

Explain the added worked example · 5

For a valid request, start at B1. Check time and the quiet condition for the current candidate. If both pass, output that candidate and stop. If either fails, move forward exactly one row.

After B4 fails, there is no next row, so output no match and stop. Never jump back to B1 within the same search.

Model the reasoning aloud · 6

The current candidate changes from B1 to B2. The request values stay the same. After B2 passes, the process stops: it does not replace B2 with a later fitting row.

This early stop preserves the first-match rule and gives the same required suggestion as the manual baseline, which marked every row before selecting the first fit.

Model the reasoning aloud · 7

Termination needs a reason. There are only four rows, each failed check moves to the next row, and no row is revisited. A valid request therefore examines at most four candidates. A success can stop sooner.

Invalid input stops before the search. Merely drawing an arrow around a loop is not enough; the state must make progress toward an end.

Why the result follows

Address these additional misconceptions

One failed row proves no match: Later rows may fit; continue until a fit or catalogue exhaustion.

Passing either condition is sufficient: The time and quiet conditions must both hold.

Any compatible answer satisfies the task: The first-in-catalogue tie rule is also a requirement.

A loop stops because it should: Show a state change that advances toward a finite end.

Explanations for the additional workbook examples

W1 Describe all possible kinds of ending

Workbook question · W1

Name the three kinds of final output in the activity process and the condition that leads to each. Explain why a candidate failing its time check is not automatically a final no-match result.

Teacher reasoning · W1

Clarification follows invalid or missing input. A suggestion follows the first candidate passing both compatibility conditions. No match follows a valid request after all candidates fail.

A single failed candidate does not settle whether later candidates fit, so the process must advance.

W3 Repair an incorrect branch

Workbook question · W3

A design says “If the activity is quiet OR its time fits, suggest it.” For 5 minutes with Quiet required Yes it selects B1. Identify the failed requirement and replace the condition with a correct one.

Give the correct result for this request.

Teacher reasoning · W3

B1 is quiet but requires 10 minutes, exceeding 5. Require time to fit AND the quiet condition to hold. The quiet condition is either quiet not required or a quiet activity.

No catalogue activity fits 5 minutes, so the correct output is no match after checking all candidates.

W4 Design a complete room decision process

Workbook question · W4

A new paper catalogue lists C1 first, capacity 4, quiet Yes; C2 second, capacity 8, quiet No. Valid requests give a whole group size from 1 to 10 and Quiet required Yes or No.

A room fits if capacity is at least group size and the quiet condition is met; choose the first fit. Write a complete process with validation, search, state change and stopping rules.

Trace 6 people No and explain the outcome for a blank quiet field. No booking takes place.

Teacher reasoning · W4

Validate group size and Yes or No; request clarification and stop if invalid. Start C1; check capacity and quiet. If both pass, suggest and stop; otherwise advance to C2. If C2 also fails, report no match and stop.

For 6 No, C1 fails capacity, C2 passes capacity with quiet unrestricted, so suggest C2. Blank quiet requires clarification before searching. Each failed row advances, so at most two candidates are checked.

W5 Preserve the first compatible option

Workbook question · W5

For the activity catalogue, 15 minutes with Quiet required No allows several activities. Explain why returning the last compatible row breaks the agreed rule even though it fits.

Teacher reasoning · W5

All four activities fit, but the tie rule requires B1 first. Returning B4 meets compatibility but not the full specification. Stop immediately after the first passing candidate.

05. Connect the explanation to its limit

A complete decision process specifies what to do after each result. One passing requirement is insufficient.

After a kit passes both, stopping preserves the first-match contract; automatically choosing the largest later kit would implement a different rule. A full scan with no accepted kit returns no match.

Limit: A correct flow depends on accurate catalogue entries and the declared requirements; the picture does not verify inventory.
