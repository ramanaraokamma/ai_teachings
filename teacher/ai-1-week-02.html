Preparation for the connected explanation

Teach input and output as relative to a stage. Avoid claiming that representations are inherently truthful or complete. This lesson introduces information loss through counterexamples, without requiring formal information theory. Explain the mechanism

Explain the mechanism

Follow the information instead of imagining magic inside the machine.

INPUT songs played, liked, or skipped

PROCESS compare clues and rank possible songs

OUTPUT a suggested song or a not-sure result

CORE IDEA A system transforms information; it does not simply 'know.'

UNDER THE HOOD Input, process, and output are functional roles. The process may contain human choices, fixed rules, calculations, retrieval, or a learned model. Naming the three stages prevents magical explanations of computer behavior.

Draw a fresh example with all three stages:

Every step connects a claim to observable evidence.

CASE A music helper receives listening choices, compares them with a ranking process, and suggests a song. The suggestion appears only after information has moved through the system.

STEP 1 — OBSERVE songs played, liked, or skipped

STEP 2 — TRACE compare clues and rank possible songs

STEP 3 — CONCLUDE a suggested song or a not-sure result

MODEL REASONING Start with what enters, name the actual transformation rather than saying the system thinks, and identify the result. If the process is unknown, state what evidence is missing instead of inventing a mechanism.

DO NOT OVERCLAIM The output is not proof that the system understood the input as a person would.

What new evidence could change this answer?

Concrete teaching case

A playlist helper receives a mood, matches song tags and displays three titles.

Name input, process and output. Is displaying titles the same as playing audio?

Exact explanation to model

Input is mood; process is tag matching; output is titles. Audio playback is another step. Matching can use fixed rules; the description alone does not establish machine learning.

Explain the added worked example

A library kiosk asks Sam for a genre. Sam selects mystery. The kiosk compares that preference with catalogue tags and displays three book titles. Sam says the kiosk has read three books aloud. That conclusion adds an action that the description never supplied: displaying a title is different from producing spoken audio.

An information path names what enters each stage, what happens there and what leaves it. Treat input and output as roles relative to a stage. A list of titles is the output of the search, but it could become the input to a separate text-to-speech stage. A component can therefore receive the output of another component without doing the same job.

The kiosk's genre-matching operation can be implemented with a written rule. Nothing in this description establishes that a model was trained. This connects to Week 1: tracing information tells us what a process needs to do, while mechanism evidence tells us how it does it.

Notice the difference between a title, a description and an entire book. All three can be text, but they represent different amounts of information. Even a speech stage receiving three titles can speak only those supplied titles; it has not thereby read the full books. Always identify the content of an input, not just its data type.

A recommendation is also different from a loan. Selecting a title does not reserve a copy unless an authorised reservation step exists. Keeping these distinctions clear prevents us from crediting a system with actions it did not take.

Model the reasoning aloud

Use the complete worked example below before asking learners to complete W2. Reveal a small part, invite a prediction, then explain the deciding step. These teacher notes contain solutions; do not reveal the independent case answer during modelling.

Consider two catalogue records. Book A has 90 pages and is about a child solving a seaside mystery. Book B has 90 pages and is about a lost spaceship. If we keep only page count, both become the number 90. The number is useful for a length limit, but it cannot tell us which story is a mystery. Information that was never retained cannot be recovered just by calculating harder.

Page count 90Is the book under 100 pages?Is its story a mystery?
Genre tag mysteryDoes it match a mystery request?Will this particular reader enjoy it?
Short summaryWhat does the description say happens?What exact sentence occurs on page 42?

The phrase cannot settle alone matters. A genre tag might be inaccurate, and a reader might enjoy an unfamiliar genre. A representation is useful only in relation to a question and its limits. More detail is not automatically better: unnecessary personal information can add risk without helping the task.

A pictorial worked case: Input, Process, Output

A fictional classroom cupboard records coloured pencils, then reports just a total.

The facts we will use

Box A has 2 red and 4 blue pencils. Box B has 5 red and 1 blue.

The process adds colour counts and stores only the total, not the two counts.

Why this result follows

Adding preserves the number of pencils but discards how that number was divided between colours. Both distinct inputs lead to the same stored output. Working backwards from 6 therefore has several possible answers; it is not an instruction to divide equally.

What this example does not establish

The two-colour assumption matters. Extra colours would prevent inferring blue from total and red alone.

Change one thing in the pictured case

Change: Store red count alongside total.

Prediction: The records become (6,2) and (6,5).

Reason: Blue count can now be recovered by total minus red, assuming these are the only colours.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Demonstrate and guide practice

Board sequence

Write the given facts: A playlist helper receives a mood, matches song tags and displays three titles.

Write the question to explain: Name input, process and output. Is displaying titles the same as playing audio?

Reveal after predictions: Input is mood; process is tag matching; output is titles. Audio playback is another step. Matching can use fixed rules; the description alone does not establish machine learning.

Keep for an independent attempt: A classroom fan receives a temperature reading, compares it with 25 degrees C, and turns on. Name the input, process and output. What should happen if the reading is missing?

Classroom dialogue

Ask: Which facts are given, and which would we have to assume? Learners mark relevant details before discussing answers.

Say: Predict first. Show the rule, information path or calculation that would produce the result. A correct guess is not yet an explanation.

Reveal reasoning one step at a time. Explain why a tempting alternative fails. Write units and denominators for arithmetic, trace conditions for decisions, and identify supporting sources for claims.

In pairs, one learner solves while the other checks evidence; exchange roles. Remove the worked answer before independent assessment.

Model these guided questions

Visitor schedules can be three at 09:00 or one each at 09:00, 10:00 and 11:00. The total does not reveal timing or busiest hour. Displaying a book title produces text on a screen; speaking needs audio generation, reserving needs an authorised availability update and reading the whole book needs its full content.

Individual reasoning check

Use the worked case for Representations and information paths. Proposed explanation: “Every output is the final action”. Decide whether this explanation is supported. Point to the step or supplied fact that decides; explain your repair if needed.

Collect explanations, not only yes/no votes. If a misunderstanding is common, re-model the relevant step for the class. If it affects a few learners, give a short targeted group explanation while others solve a more demanding variation.

Diagnose and reteach

CLAIM TO REPAIR The fan's movement is the input.

For guessing, return to given facts and request a trace. For vocabulary without application, use one example and one non-example. For arithmetic errors, check the setup before the calculation. Finish with a different uncoached case before recording mastery.

Address these additional misconceptions

Every output is the final action: Trace an output entering the next stage. Ask whether the borrowing or speech stage exists and has run.

More calculation can recover discarded details: Ask students to distinguish two original records with the same retained value. No deterministic calculation of that value alone can know which original occurred.

A data type tells us what the data means: Compare a title, a summary and a full chapter. All can be text while supporting different questions.

Independent question

A classroom fan receives a temperature reading, compares it with 25 degrees C, and turns on. Name the input, process and output. What should happen if the reading is missing?

Expected independent answer

Input is the reading; process is comparison with 25 degrees C; output is the fan command. A missing reading calls for a fault signal or human review, not an invented temperature.

Explanations for the additional workbook examples

W1 Trace a request

The kiosk receives genre=science and maximum pages=120. The catalogue contains A science 80 pages, B science 150 pages and C mystery 90 pages. It keeps records with the requested genre and no more than 120 pages. Draw the input, process and output, naming the surviving record.

Input includes both request fields and all three catalogue records. The process checks science AND pages<=120. Output contains A only; B fails the length condition and C fails the genre condition. Listing A does not establish that a copy was reserved.

W2 Finish the visitor example

A record stores only total visitors=3. Give two different arrival schedules that produce this total. Can the total tell us the busiest hour? Explain.

Examples: three visitors at 09:00, or one each at 09:00, 10:00 and 11:00. Both total 3, but their busiest-hour patterns differ. The total lacks arrival-time information, so the busiest hour cannot be recovered from it alone.

W3 Choose a sufficient representation

For each task, choose the information needed: decide whether a book is under 120 pages; quote its first sentence exactly; decide whether a copy is available now. Explain why a genre tag alone is insufficient for all three.

Use the page count for the length condition, the actual first sentence from the correct edition for an exact quote, and a current copy-availability record for availability. Genre supplies none of those facts. Even suitable records must be checked for the correct edition or time.

W4 Investigate a new loss of information

A classroom device receives four scores and stores only their total, 20. A student claims that every score must be 5. Give two different lists of four nonnegative whole-number scores with total 20. Explain precisely what the stored total establishes and what it does not.

For example [5,5,5,5] and [2,4,6,8] both total 20. The stored total establishes the sum under the stated recording process, but not the individual scores or their equality. A list with fewer than four entries or a different total is not a valid counterexample.

W5 Diagnose before repairing

A voice calculator receives a spoken request for 16 divided by 4. Its transcript says 60 divided by 4 and its calculator returns 15. Identify the first incorrect stage, show the intended result and propose a check before calculation.

Transcription first changes 16 to 60. The calculator correctly computes the wrong supplied expression. The intended result is 4. Display or confirm the interpreted numbers before calculating, rather than changing the arithmetic code to force the expected answer.

Feedback that the learner uses

Name the earliest unsupported step and give one action to repair it. Have the learner make that repair now and explain why. Then assess the relevant skill on a fresh, fully specified case. Confirm it was not previously practised with feedback; solve and check the new case before assigning it. A follow-up design prompt is a starting brief, not automatically an equivalent test.

Support and stretch

Use physical cards, spoken explanations and a three-stage drawing. Read aloud without giving the answer. Stretch: compare two mechanisms with the same visible output and explain what evidence distinguishes them.

Exit reflection

Ask for one decision the learner can now justify and one situation requiring more evidence or human review. Confidence ratings are separate from correct independent performance.

Bridge to the next week

Next: Week 3: Sensors Are Messengers. Retrieve today’s evidence and identify what carries forward and what is new.

Support and fresh reassessment

Provide four empty boxes and counters for learners who need arithmetic support. Let them explain information loss orally. Extension: ask which extra field, such as minimum score, would rule out one of their lists and whether it would uniquely determine the original list.

W4 is secure when both lists contain four nonnegative whole numbers, both sum to 20, at least one is not all fives, and the explanation distinguishes sum from individual values. If the learner offers only one list, request another record consistent with the same total. Use a different total for the uncoached retry.
