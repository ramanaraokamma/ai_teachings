Explain the added worked example · 3

Keep the P1 version 1 instructions from Week 32: validate and stop with clarification if input is invalid; otherwise start at B1, check both conditions, suggest the first passing row and stop.

After a failure advance one row; report no match only after all rows fail. Reset to validation and B1 for each new valid request. The manual baseline marks every row against both conditions and selects the first fit.

Both methods must follow the same contract.

Explain the added worked example · 4

Give each case an ID. Record its exact input, purpose, expected output and expected explanation before running it. Then add observed output, observed explanation, pass or fail, and a trace reference.

Put the prototype version, catalogue version and baseline method at the top of the sheet.

A pass needs the correct result and a reason supported by the checked conditions; the right activity with a false reason is not a full pass.

Demonstrate and guide practice

Demonstrate Test Normal Cases, reduce support deliberately and check individual reasoning before discussing answers.

Board sequence

1. Put the facts on the board

Write the given facts: Four routine cases are chosen before testing. Three are correct.

2. State the decision to explain

Write the question to explain: What can be reported?

3. Reveal the worked reasoning

Reveal after predictions: 3/4 on those cases. Preserve the failure and trace its cause. This does not guarantee unfamiliar-case performance.

Hold back the independent task

Keep for an independent attempt: Test a sorter on two clear pencil cards and two clear book cards. It gets one book wrong. Report the result and keep the failed case.

Classroom dialogue

Ask the class

Ask: Which facts are given, and which would we have to assume? Learners mark relevant details before discussing answers.

Language to model

Say: Predict first. Show the rule, information path or calculation that would produce the result. A correct guess is not yet an explanation.

Reveal reasoning one step at a time. Explain why a tempting alternative fails. Write units and denominators for arithmetic, trace conditions for decisions, and identify supporting sources for claims.

In pairs, one learner solves while the other checks evidence; exchange roles. Remove the worked answer before independent assessment.

Model these guided questions

Q has 3 of 4 full passes and the fictional baseline 4 of 4. R4 selects B2 despite the quiet requirement. Dropping R4 answers how Q did on a selected three-case subset and conceals the failure in the original set.

Gaps include missing or invalid fields, equality at thresholds, accepted range endpoints and successful later-row selection under a varied catalogue.

Exit: this named version passed these four routine cases under the recorded conditions; all-input correctness and a speed advantage are not established.

Two distinct useful checks could be invalid-input handling and equal-time boundaries. Measuring speed would require a separate fair timing comparison.

Address these additional misconceptions

A correct label is always a full pass: The agreed criterion also requires a correct explanation.

Remove a failed run because something went wrong: Keep and investigate it; missing required output cannot count as success.

Four passes prove all inputs work: The conclusion is limited by the selected cases and conditions.

The prototype must beat the manual baseline: A correct simple baseline can tie or outperform a prototype; report the evidence.
