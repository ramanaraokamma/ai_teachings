Explain and model the mechanism

Model Dictionaries and records using the supplied case, labelled mechanism and reasoning. Make the scope of each conclusion explicit.

A fictional cupboard record has a name, capacity and used count. A list asks us to remember positions. Named fields make the intended meaning visible.

Our schema requires name as text and capacity and used as nonnegative integers, with used no greater than capacity.

Square brackets look up the value for a key. The quoted key "used" is text; its value is an integer. Assigning to an existing key replaces that field. Other fields remain the same.

Dictionary syntax does not enforce our schema: the programmer must check it.

TermMeaning
DictionaryA mapping from unique keys to values
KeyA name used to look up a value
RecordRelated fields describing one item
KeyErrorThe error from looking up an absent dictionary key

Spaces are 0. A present used field with value 0 is different from an absent field. Exit: No. The used count exceeds capacity. Successful arithmetic does not validate the record.

Require field lookups rather than copied literal arguments.

A convenient shortcut preserves meaning: cupboard["Used"] raises KeyError here because keys are case sensitive. Correct it to "used".

Adding a new field called "Used" would create a second key and leave the original unchanged; it would not repair the intended lookup.

def describe(record):
    count = record.get("count")
    if count is None:
        return "missing"
    return count
record = {"count": 0}
print(describe(record))
record["count"] = 3

Selected case answer

Teacher key · Selected case answer

Outputs are0,3,missing. A stored0 is a supplied value; an absent field returns None under get here. The update replaces count with3 before the second call.

Using if not count would incorrectly return missing for the original count0 because zero is false in a Boolean test; testing None keeps absence separate.
