A pictorial worked case: Rows Columns and Data Types

A fictional approved book catalogue has three fields per row.

The facts we will use

Schema: id is nonempty text; pages is an integer 1–300; illustrated is Boolean True or False.

Rows A={id:"B7",pages:90,illustrated:True}; B={id:"B8",pages:"90",illustrated:False}; C={id:"",pages:80,illustrated:True}.

Why this result follows

A schema makes row meanings and expected types explicit. The string "90" looks like a number when printed but does not meet this strict integer schema. A repair can be authorised later, but must not be assumed silently. Missing or empty identifiers also prevent tracing an item back to its source.

What this example does not establish

Schema validity does not confirm that the book really has 90 pages or that its metadata is accurate.

Change one thing in the pictured case

Change: Change B’s pages from "90" to integer 90 using an approved repair.

Prediction: B now satisfies the declared schema.

Reason: Its id is nonempty and illustrated is Boolean; the page-type defect is removed.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Diagnose and reteach

For guessing, return to given facts and request a trace. For vocabulary without application, use one example and one non-example. For arithmetic errors, check the setup before the calculation. Finish with a different uncoached case before recording mastery.

Address these additional misconceptions

A successful run proves the conclusion: A row can satisfy every schema rule and still be a wrong observation. Schema validation checks our stated structure and constraints, not whether someone measured honestly or selected a representative sample.

Matching the example is enough: Require the new W4 case, explicit predictions and an explanation. Fresh retry: define a tray label and integer count 0 through 20. Require tests at 0, 20, -1 and 21 and a text count.

A convenient shortcut preserves meaning: If one row records 120 seconds in the minutes field, a simple numeric total becomes misleading. Correct the source or explicitly convert and document it; renaming a column alone does not convert values.

Explanations for the additional workbook examples

W1 State a schema

List the required fields, types and duration boundaries for the worked table.

activity: nonempty text; minutes: integer from 0 to 60 inclusive.

Check both fields. activity must exist as nonempty text. minutes must be an exact integer and satisfy 0 <= minutes <= 60. Inclusive means equality is accepted at both ends. Structure, type and range are separate checks; passing them does not prove the duration was measured accurately.

W2 Classify records

Classify minutes values 0, 60, -1 and 61 under this schema.

0 and 60 pass; -1 and 61 fail.

Apply the inclusive range to each integer. Both 0 and 60 are on allowed boundaries. -1 is below the minimum and 61 is above the maximum. Require the reason for each rejection, not only pass/fail labels.

W3 Repair a unit problem

A source says 180 seconds but the row says minutes: 180. Give a documented correction.

Divide by 60 to record 3 minutes and retain the source value and conversion note.

W4 Design a schema independently

For a fictional shelf audit, define label and book_count fields. Require a nonempty text label and an integer count from 0 to 40. Give two valid and two invalid records with reasons.

Examples: A/0 and B/40 valid; empty label/5 invalid label; C/41 invalid range. Text "5" also fails the count type. Accept alternatives meeting the written rules.

W5 Separate validity and truth

A row says Reading, 12 and passes. Does that establish the session really lasted 12 minutes?

No. The value has a permitted structure but still needs trustworthy collection evidence.
