Explain and model the mechanism

Gradient descent uses new parameter = old parameter - learning rate times its gradient entry. The minus sign chooses the locally downhill direction for a positive learning rate. A negative gradient therefore increases the corresponding parameter.

Keep the Week 10 example: x = 2, target 3, y = 2w + b and L = (y - 3) squared. At [w, b] = [1, 0], the loss is 1 and gradient is [-4, -2]. With learning rate 0.1, new w = 1 - 0.1 times -4 = 1.4 and new b = 0 - 0.1 times -2 = 0.2.

This particular step reaches zero loss on one example. It does not establish a unique parameter solution, successful learning on other examples or a generally ideal learning rate.

Predict the rows: unchanged parameters and loss 1 at rate 0; [1.2, 0.1] and loss 0.25 at rate 0.05; [1.4, 0.2] and loss 0 at rate 0.1; [2.2, 0.6] and loss 4 at rate 0.3. The helper performs one step on this fixed example; it assumes numeric inputs and does not choose a learning rate for you.

TermMeaning
Learning rateA multiplier that controls the size of a gradient update
Gradient descentUpdating parameters in the direction opposite the gradient
Simultaneous updateComputing all new parameter values from the same old state
OvershootA step that moves too far and can increase the objective

Guided: [1.2, 0.1] gives prediction 2.5, residual -0.5 and loss 0.25. Exit: no. The mixed-state procedure lowers this loss but does not implement the specified simultaneous gradient step; compare states and gradients, not just whether loss decreased.

A pictorial worked case: Updating parameters

Use one explicit gradient update and then recompute the loss.

The facts we will use

Model y=2w+b, target 5. Start w=1, b=1; learning rate 0.05. Initial y=3, error y−target=−2, squared loss 4.

All inputs and outcomes in this worked example are invented classroom data; no real model run is claimed.

Why this result follows

Gradient descent subtracts learning rate times gradient. A negative gradient makes this subtraction increase the parameter. Compute both gradients at the original [w,b] before updating either one. The small step brings the prediction closer to five, reducing squared error. A larger step can cross the target and undo that gain, so the new prediction and loss must be recalculated.

What this example does not establish

One successful toy update is not evidence of convergence for a real network or generalisation to unseen data.

Change one thing in the pictured case

Change: Set learning rate 0.2 from the same starting point.

Prediction: New w=2.6, b=1.8, y=7, squared loss 4: no improvement.

Reason: The larger update jumps to an equally distant point on the opposite side of the target.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Teacher guide · 4 of 8

Run the investigation and diagnose misconceptions

Subtracting a negative gradient decreases the parameter: Subtracting a negative adds a positive amount; show the signed calculation.

A downhill direction allows any rate: A finite step can overshoot and increase loss.

Recompute each gradient after its assignment: For this algorithm, all entries are computed at the same saved state.

Use Section 9 for the evidence ledger. Add a boundary or missing-input case and record the expected response before checking. More successful repeats of one case do not establish wider coverage.

The feedback comes from the reviewed public worked case. Do not reveal the separately reserved independent teacher answer until the learner has attempted that case.

Ask students to predict before running code. Preserve errors and actual outputs; collect a changed test and an explanation. The branch-boundary and indexing lessons deliberately include failure cases.
