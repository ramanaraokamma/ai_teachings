Training data fits the model. Validation data helps compare choices such as candidate rules. Keep the test set for a final check after those choices are fixed.

Optional training-only scaling extension

This optional extension introduces a fixed one-nearest-neighbour example; the main nearest-neighbour lesson comes later in Week 12. With two features, their numerical ranges can give one feature much more influence. Scaling changes those contributions. We will learn a minimum and range for each feature from training only, then reuse them for every example.

These fictional trips have a distance reading in cm, a brightness reading in sensor units and a reviewed lane label. Features are available before prediction; labels are separate evidence.

Related trips have already been grouped before splitting. For this exercise use k=1, add absolute differences across the two features, and break equal distances by alphabetical ID.

For query (11,120), raw distances to A,B,C are 1+80=81, 9+20=29 and 9+80=89. B wins and predicts blocked. Adding these different units is an unscaled numerical choice; the large brightness range strongly affects it.

Scaling offers another explicit distance choice, not proof of which features matter.

For each feature use scaled value = (value minus training minimum) divided by training range. range(2) visits feature positions 0 and 1.

The code prints [10, 100] [10, 100], then [(0.0, 1.0), (1.0, 0.0), (1.0, 1.0)], then (0.1, 0.2). Each minimum becomes 0 and each maximum becomes 1.

The first calculations fit low and span from train. transform uses those stored values without learning new ones. The code assumes nonempty training rows with exactly two finite numeric features; it does not check all inputs.

Its explicit zero-range guard stops division by zero so a constant feature can be reviewed. This is a classroom policy, not a claim that every library stops this way.

Guided: raw distances A,B,C are 81,29,89 so B predicts blocked; scaled distances are 0.9,1.1,1.7 so A predicts clear. Keep minima (10,100), ranges (10,100), feature order and method settings fixed.

Exit: even unlabelled evaluation features affected the fitted transformation. Split first, fit minima and ranges on training, transform every split with those values, then evaluate frozen predictions.

Diagnose the current misconceptions

Different row IDs mean independent examples: Different frames may share a trip or source. Choose group metadata based on the claim and verify it against the source.

A fixed percentage guarantees a fair test: Percentages do not remove overlap or ensure enough groups and relevant cases. The goal and dependencies determine the split.

An empty overlap list proves there is no leakage: The audit checks listed group IDs only. Wrong metadata, copied content, outcome features or preprocessing fitted on all sets can still invalidate evaluation.

Extension misconceptions

Every transformed value must lie between 0 and 1: Only the fitted training range maps to 0 through 1. New values outside that range can transform below 0 or above 1.

No labels means no leakage: Held-out feature values can leak into a learned transformation. Fit preprocessing on the training split only.

Scale each split separately: Separate fits create different coordinates. Apply the same stored scale to training examples and queries.
