Explain and model the mechanism

In Week 12 every update used both training examples. We now keep the same network h = ReLU(x), y = vh, with only v trained, and divide the data into batches. In this lesson each nonempty batch produces exactly one update. An epoch visits every training example exactly once, without replacement. These rules make the counts unambiguous.

Imagine five fictional records A through E in fixed order. With batch size 2, the groups are [A, B], [C, D] and [E]. Keep the smaller last batch. One epoch has three batches and three updates; two epochs have six updates and ten example visits.

When the last batch is retained, updates per epoch equal the row count divided by batch size rounded up. A program that drops the final incomplete batch follows a different rule and omits examples in that pass. Record the rule instead of silently changing the denominator.

Use the two fictional pairs A = (1, 2) and B = (2, 4), start v = 0 and rate 0.1. For one pair with hidden value h, squared-error gradient is 2 times (vh - target) times h. For a batch, average these gradients at the same current v. Apply one update, then recompute for the next batch.

Assume finite numeric pairs, integer size and finite rate. With size 1, A gives gradient -4 and new v = 0.4. B then uses 0.4, giving prediction 0.8, residual -3.2 and gradient -12.8, so v becomes 1.68. With size 2, both gradients are evaluated at v = 0; their mean is -10, producing v = 1.

TermMeaning
BatchA group of training examples used together to calculate one gradient here
UpdateOne application of the gradient and learning rate to the current parameters
EpochOne pass through all training examples under the stated sampling rule
Batch sizeThe intended number of examples in each batch with a possible smaller final batch

Guided: B at v = 0 gives gradient -16 and v = 1.6. A then gives residual -0.4, gradient -0.8 and v = 1.68. Two batches each cause one update. Exit: both teams visit ten examples. Size 2 produces six updates; size 5 produces two. Record both budgets and all training settings.

A pictorial worked case: Batching and epochs

Show why an epoch’s example order can matter for single-example updates.

The facts we will use

Toy y=wx, rate 0.1, squared loss, start w = 0. Training A=(x = 1, target 2), B=(x = 2, target 0).

All inputs and outcomes in this worked example are invented classroom data; no real model run is claimed.

Why this result follows

A single-example update changes the weight before the next example’s gradient is calculated. Reversing the example order can therefore change the path. A full-batch update computes both gradients at the same starting weight and averages them before changing that weight. The distinction is when the update occurs, not whether the examples have different labels.

What this example does not establish

Different order effects do not mean a universally better batching strategy; compare declared schedules and budgets fairly.

Change one thing in the pictured case

Change: Use only one full-batch update after reversing record order.

Prediction: The updated weight remains 0.2.

Reason: The same mean of the two starting gradients is unchanged by their order.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Run the investigation and diagnose misconceptions

One epoch always means one update: Only a full-data batch gives one update per epoch in this procedure.

Reuse all gradients from the start of an epoch: Recompute at the parameter value before each batch update.

Average batch means equally: At one fixed model, weight each batch mean by the number of examples in that batch.

W3 Combine unequal batches

At one frozen model, batches of sizes 3 and 1 have mean squared errors 2 and 10. Find the full MSE and explain why the average of 2 and 10 is wrong.

Teacher explanation: Full MSE is (3 times 2 + 10) / 4 = 4. The unweighted average 6 gives the single-row batch too much weight.

W4 Test order on a new case independently

Use A = (1, 1), B = (2, 0), h = ReLU(x), y = vh, v = 0 and rate 0.1. Train with size 1 for one epoch in A then B order, then restart at 0 and reverse the order. Show gradients and parameter values. Compare the final values.

Teacher explanation: A then B: A gradient -2 gives v = 0.2; B residual 0.4 gives gradient 1.6 and v = 0.04. B then A: B gradient 0 keeps v = 0; A gradient -2 gives v = 0.2. Both see the same rows but finish differently.

W5 Audit an epoch claim

A program processes 11 rows using size 4 and drops the last incomplete batch. How many examples did it visit and how many updates occurred? What must its report disclose?

Teacher explanation: It visits eight rows in two batches and performs two updates. Three rows are omitted; it did not complete a full pass under this lesson definition. Report the drop rule and actual visits.
