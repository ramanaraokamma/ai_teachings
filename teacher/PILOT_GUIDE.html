Choose and schedule

Choose the track that matches actual readiness. Record the class or anonymous group code, approximate group size and actual dates. The three tracks sample different readiness stages; learners do not need to complete all three.

  1. Before teaching, check prior exposure and collect the baseline without hints.
  2. Teach the complete selected lesson, using its staged plan and support where needed. Record time and barriers rather than forcing a fixed pace.
  3. Collect the post-lesson independent case before feedback. Record any help separately.
  4. Return after a teaching delay, such as one week when appropriate; use the held-back changed task before reviewing old answers.
  5. Compare only learners with matching baseline and later records. Review explanations, traces and limits; do not treat a quiz selection or progress tick as mastery.
  6. Repair confusing wording, pictures, examples or timing, and repeat on a fresh case. Preserve the actual evidence and revision.

The tasks differ, so observations are descriptive. This small pilot cannot establish that the lesson caused a learning gain. A real teacher and learners must carry out the sessions.

Foundations: explain a hybrid system

Distinguish an observed result from an explanation of how it was produced

Ask whether learners have seen any selected case before. Mark prior exposure; use a genuinely different teacher-checked case when a selected task is familiar.

Baseline task — hold back until the relevant session

A classroom door opens when someone approaches. Its label says intelligent entrance. State one observation, one mechanism you cannot determine from that observation, and one record or question that would help distinguish a written rule from a learned model.

Print the selected learner handout (without answers)

Teacher reasoning key

Opening on approach is an observation. The decision mechanism is unknown. Ask for the rule or training record and trace how an input produced the action; an intelligent label does not establish learning.

Post task — hold back until the relevant session

A school greenhouse estimates tomorrow's temperature using a model fitted on historical weather. A written rule displays CHECK PLANTS above 30 degrees C. A caretaker chooses whether to open a vent. Identify each mechanism and explain why a correct CHECK PLANTS message would not prove an accurate temperature prediction.

Print the selected learner handout (without answers)

Teacher reasoning key

The forecast is learned-model prediction; the message is a written threshold; vent opening is the caretaker's decision. The message may correctly follow a forecast that is itself inaccurate. Compare the forecast with a predefined temperature observation at the relevant place and time before judging prediction accuracy.

Delayed task — hold back until the relevant session

A bus station estimates the number of waiting passengers using a model fitted on labelled camera frames. A written rule displays CALL ANOTHER BUS at estimates of 35 or more. A dispatcher chooses whether to send a bus. The estimate is 40. Identify the three mechanisms, trace the message, and explain why a correctly displayed message does not prove an accurate passenger estimate.

Print the selected learner handout (without answers)

Teacher reasoning key

The estimate is a learned-model prediction; the message follows the written threshold (40 >= 35); dispatch is human action. The threshold can be applied correctly to an inaccurate estimate. Compare the estimate with an appropriately timed, predefined passenger count before judging prediction accuracy.

Python: branch order and boundary tests

Trace the selected branch in an if elif else chain

Ask whether learners have seen any selected case before. Mark prior exposure; use a genuinely different teacher-checked case when a selected task is familiar.

Baseline task — hold back until the relevant session

Trace the code for reading=20, then reading=19 and reading=101. Explain why validity is checked before the lamp rule.

reading = 20
if not 0 <= reading <= 100:
    action = "invalid"
elif reading < 20:
    action = "on"
else:
    action = "off"
print(action)

Print the selected learner handout (without answers)

Teacher reasoning key

20 gives off, 19 gives on, 101 gives invalid. Validity is checked first so invalid inputs cannot be treated as valid lamp decisions.

Predict the action for 30, then trace 29 and -1. Explain why validity is checked before the lamp decision.

reading = 30
if not 0 <= reading <= 100:

Teacher reasoning key

30 gives off, 29 gives on, -1 gives invalid. Checking validity first prevents an invalid negative reading from being accepted as a lamp-on decision.

Delayed task — hold back until the relevant session

Write or trace a branch chain: valid readings are 0 through 100 inclusive. Invalid readings produce invalid; valid readings below 25 produce on; all other valid readings produce off. Predict 24,25,100,101 and -1, then justify the order and boundaries.

reading = 25
if not 0 <= reading <= 100:
    action = "invalid"
elif reading < 25:
    action = "on"
else:
    action = "off"
print(action)

Print the selected learner handout (without answers)

Teacher reasoning key

24 on; 25 off; 100 off; 101 invalid; -1 invalid. Check validity before the threshold, include both valid endpoints, and use a strict less-than comparison for on.

Machine Learning: fit and compare a baseline

Fit a majority label baseline using training labels only

Ask whether learners have seen any selected case before. Mark prior exposure; use a genuinely different teacher-checked case when a selected task is familiar.

Baseline task — hold back until the relevant session

Training labels are A,A,B. Validation labels are A,B,B. Fit a training-majority baseline and list its three predictions. A candidate predicts A,B,A. Score both on these validation rows, state the difference in correct examples and percentage points, and name an unsupported claim.

Print the selected learner handout (without answers)

Teacher reasoning key

Fit A from the training majority. Predict A,A,A. Baseline gets row 1: 1/3. Candidate gets rows 1 and 2: 2/3. It gains one correct example and about 33.3 percentage points. This tiny comparison does not establish performance on future cases.

Post task — hold back until the relevant session

New training labels are blocked, clear, blocked, blocked, clear. New validation labels are clear, blocked, clear, blocked. Fit the same baseline rule and list its four predictions. A supplied candidate predicts clear, blocked, blocked, blocked. Score both on these rows and state the difference in correct examples and percentage points. What claim remains unsupported?

Print the selected learner handout (without answers)

Teacher reasoning key

Training counts are three blocked and two clear, so predict blocked four times. The baseline matches rows 2 and 4: 2/4 or 50 percent. The candidate matches rows 1,2,4: 3/4 or 75 percent. It gains one correct example and 25 percentage points. This tiny validation comparison does not prove future performance or readiness for use.

Delayed task — hold back until the relevant session

Training labels are blue,red,blue,blue,red. Validation labels are blue,red,red,blue,blue. Fit the training-majority baseline and list its five predictions. A candidate predicts red,red,blue,red,blue. Score both, state the difference in correct examples and percentage points, and explain the limit of this comparison.

Print the selected learner handout (without answers)

Teacher reasoning key

Training has three blue and two red, so predict blue five times. Baseline matches rows 1,4,5: 3/5 or 60%. Candidate matches rows 2,5: 2/5 or 40%. It loses one correct example and is 20 percentage points lower. The small validation set does not establish future performance or suitability for deployment.

Judge the recorded evidence

For explanation, trace/test and limits, record not yet, with support or independent. Keep a learner quote, written response or described demonstration. Record support used, actual minutes, confusing language, access barriers and the next teaching action.

Use anonymous learner codes. The hosted teacher pilot studio stores records in the current browser and exports CSV/JSON. Keep a downloaded record before clearing a shared device. Student accounts cannot open the studio or teacher reasoning keys.
