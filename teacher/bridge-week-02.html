Explain and model the mechanism

A count and a shelf label can look similar while needing different operations. The integer 8 is a number; "08" is text that preserves a leading zero. You can count eight objects, but adding two shelf labels is usually meaningless. This week you will examine values, trace changes to names and explain which representation a task needs.

Use the saved Python 3 script workflow from Week 1. Make a new file values.py, predict before running and keep actual output separately. Use fictional labels only. Four useful types are int for whole numbers, float for floating-point numbers, str for text, and bool for True or False. A type describes a value, not whether its meaning is sensible for the task.

type(count) produces the type of the value bound to count. These print lines display <class 'int'> and <class 'str'>. The quotes in "08" mark text; they are not displayed by print(shelf). True and False have capital initials and no quotes. "False" is text, not a Boolean.

TermMeaning
ValueA piece of data such as 8 or a text label
VariableA name bound to a value during execution
TypeA category of value that determines available operations
StringA sequence of text characters
ReassignmentBinding an existing name to a new value

The new saved = count binds saved to the current 10, so print(saved) displays 10. Without that assignment it stays 8. Exit: turning "08" into 8 loses the leading zero; identifier addition has no defined meaning in the stated task. -3 is an integer but cannot be a nonnegative count.

Model the reasoning aloud

Use the complete worked example below before asking learners to complete W2. Reveal a small part, invite a prediction, then explain the deciding step. These teacher notes contain solutions; do not reveal the independent case answer during modelling.

count = 8
saved = count
count = count + 2
print(count)
print(saved)

The outputs are 10 and 8 on separate lines. saved = count uses the value available at that moment. It does not store a formula that keeps following count. count = count + 2 is valid assignment: read the old 8, calculate 10, then rebind count. It is not a claim that 8 equals 10.

A pictorial worked case: Values variables and types

A number and its printed-looking text. A program stores a numeric badge count and a string that looks like that count.

The facts we will use

Python 3: count=8; tag="8"; print(count+2); print(tag+"2").

Why this result follows

Values carry types, not merely appearances. The plus operator performs numeric addition for these integers and concatenation for these strings; the mixed operation is invalid here.

What this example does not establish

These examples use built-in integers and strings; operator behaviour depends on types and is not proof of general model reasoning.

Change one thing in the pictured case

Change: Change count to 10, leaving tag unchanged.

Prediction: The two valid outputs become 12 and 82.

Reason: Only the integer variable changes; the string still contains the character 8.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Pictorial practice question

Predict both print outputs and explain why they differ. Does count+tag work, and what happens to each valid output after count becomes ten?

Reasoned teacher answer

The outputs are 10 and 82. The first adds integers; the second joins strings. count+tag raises TypeError. Changing count to 10 yields 12, while tag+"2" remains 82.

Changed-case reasoning: The two valid outputs become 12 and 82. Only the integer variable changes; the string still contains the character 8.

Collect each learner’s explanation before discussion. Use the first missing connection between input, deciding step and result to choose support. This question is worked-case practice, not fresh mastery evidence.

Teacher guide · 4 of 6

Run the investigation and diagnose misconceptions

Digits always mean a number: Quotes make a string, even when every character is a digit.

Changing one scalar name updates every earlier assignment: Trace the value bound at each assignment; no formula link is stored.

The right type guarantees valid data: A negative integer can be an invalid object count.

Lowercase false is Python’s Boolean false value: The literal is False; lowercase false is a name and is undefined in a fresh script.

Use Section 9 for the evidence ledger. Add a boundary or missing-input case and record the expected response before checking. More successful repeats of one case do not establish wider coverage.

W1 Identify the value and its type

Classify 12, 1.5, "12", False and "False". Explain why the last two are different.

12 is int; 1.5 is float; "12" is str; False is bool; "False" is str. Quotes mark text even when the characters spell a Boolean name.

W2 Trace a saved value

Trace the five-line count and saved program. Record both printed outputs, then predict the result of assigning saved = count after the change. Check with a run or label a paper trace.

Original outputs 10 then 8. After the new assignment, saved becomes 10. Keep actual observations separate. Reading an integer value earlier does not create a live link to another name.

W3 Diagnose the operation

Predict 6 + 3, "6" + "3" and "6" * 3. Explain what happens for "6" + 3. Which expression counts six groups of three?

9, text 63, text 666, and TypeError respectively. Six groups of three needs numeric multiplication 6 * 3, giving 18; none of the listed successful expressions calculates that total.

W4 Trace a new pair of names independently

A fresh script runs seats = 12; booked = seats; seats = seats - 5; print(seats); print(booked), with each statement on a separate line. Predict both outputs. Then add booked = seats + 1 and print(booked). Explain the evaluation order and choose a type for a seat label "07".

The outputs are 7 and 12, then 8 after the added assignment. The right side reads the current seats value 7 before binding booked to 8. The seat label remains str to preserve its leading zero.

W5 Separate type from validity

Give a suitable type for a counter count, a length of 2.5 metres, a shelf ID with a leading zero, and a yes-or-no availability flag. Give a count value with the right type that should still be rejected.

Use int, float, str and bool respectively. A negative integer such as -3 has type int but is invalid for a nonnegative physical count. Type checking and checking the task’s permitted values are different.

Independent assessment and fresh retry

W4 needs outputs 7, 12 and 8 with a right-side-first explanation and str for "07". After support, retry with stock = 9, spare = stock, stock = stock - 4: printing stock and spare gives 5 and 9; spare = stock + 2 then gives 7. Record independent reasoning before giving the retry.

Assess independent transfer

Selected case: Predict both output lines and explain why estimate stays unchanged when count is reassigned. Repeat the trace with initial count=0. Explain why note is text even though its printed characters look like a number.

count = 4
note = "4"
estimate = count / 2
fits = count <= 5
count = count + 3
print(count, note, estimate, fits)
print(type(count).__name__, type(note).__name__, type(estimate).__name__, type(fits).__name__)

Selected case answer

Original outputs: 7 4 2.0 True, then int str float bool. Estimate was calculated as 2.0 before reassignment; it is not a live formula. With initial count=0: 3 4 0.0 True, with the same types. Note is the quoted string "4", independent of the integer count.
