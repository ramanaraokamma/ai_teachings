Explain the mechanism

Explain the mechanism

Follow the information instead of imagining magic inside the machine.

INPUT starting state and repeat count

PROCESS run the loop body and update progress

OUTPUT finished pattern when the stop condition is met

CORE IDEA A loop repeats a useful step until a stopping condition is met.

UNDER THE HOOD A loop requires an initialization, body, update, and termination condition. Repetition is safe only when each iteration moves state toward stopping; otherwise the loop may run forever or the wrong number of times.

Draw a fresh example with all three stages:

Every step connects a claim to observable evidence.

CASE Instead of writing draw-side and turn four times, a square algorithm can repeat those steps four times.

STEP 1 — OBSERVE starting state and repeat count

STEP 2 — TRACE run the loop body and update progress

STEP 3 — CONCLUDE finished pattern when the stop condition is met

MODEL REASONING Place only the repeated steps inside the loop, initialize the counter, update it once per pass, and stop after the required count. Trace each iteration to catch one-too-many or one-too-few errors.

DO NOT OVERCLAIM Repeat forever is not an efficient algorithm unless endless operation is truly the goal and can be stopped safely.

What new evidence could change this answer?

Concrete teaching case

Repeat take the next unstamped card and stamp it four times.

How many cards are stamped? What assumption matters?

Exact explanation to model

Four, provided four unstamped cards exist and each repeat takes the next one. A limit or end-of-stack check prevents continuing indefinitely.

Explain the added worked example

A paper counter starts at 1. While the counter is below 7, add 2 to it. When the test is false, report the counter and stop. The word while means test first, run the body only if true, then return to the test using the updated value. The body here is just add 2.

The counter follows 1, 3, 5, 7. At 1, 3 and 5 the condition is true, so each test is followed by one addition. At 7 the condition is false. No addition follows that final test. The loop has three iterations and reports 7.

Compare the Week 10 instruction if counter is below 7, add 2, then report. From 1 that single decision reports 3. A while loop explicitly returns to its test; an if decision does not. Draw a pointer to the instruction being executed instead of deciding for yourself when to repeat.

The trace has four tests but only three iterations. The false test is evidence that this run stops. A list ending at 5 would be incomplete, while a list continuing to 9 would include an addition the loop did not authorise.

Write the current value, the test result and the action on every row. Repeated values can matter: if the body does not change the state used by the test, the same true test may occur again. Do not erase these rows simply because they look unhelpful.

Model the reasoning aloud

Use the complete worked example below before asking learners to complete W2. Reveal a small part, invite a prediction, then explain the deciding step. These teacher notes contain solutions; do not reveal the independent case answer during modelling.

While tests before the body. If the first test is false, the body runs zero times. Do not add 2 once just because a loop is present. Starting at 7 or 8 is a useful test of this rule.

A loop that stops when the counter is no longer below 7 does not promise to finish at exactly 7. Starting at 6 produces 8. Passing the boundary is allowed by these instructions. Always report the actual final state instead of replacing it with the threshold.

A pictorial worked case: Repeating Efficiently

A fictional paper counter advances through a display until its condition becomes false.

The facts we will use

Start at 2. While the current counter is below 10, add 3.

Test before each addition; report when the condition is false.

Why this result follows

The condition checks whether to do the next update; it does not constrain every resulting value to stay below 10. The final 11 is therefore allowed by this procedure. Record both the condition and counter to distinguish a correct stop from an assumed endpoint.

What this example does not establish

This loop stops because positive increments eventually cross the limit. Other updates can fail to make progress.

Change one thing in the pictured case

Change: Start at 10 instead of 2.

Prediction: The loop runs zero times and reports 10.

Reason: Its first condition is already false, so no addition happens.

Ask while showing the picture

Cover the result. Ask learners to name the inputs and predict the next step. Uncover one step, connect the icon to the actual procedure, and explain its evidence. Then change the supplied condition and compare. The picture is a representation; it does not document execution of a real AI model.

Demonstrate and guide practice

Demonstrate and guide practice

Board sequence

Write the given facts: Repeat take the next unstamped card and stamp it four times.

Write the question to explain: How many cards are stamped? What assumption matters?

Reveal after predictions: Four, provided four unstamped cards exist and each repeat takes the next one. A limit or end-of-stack check prevents continuing indefinitely.

Keep for an independent attempt: Repeat clap then tap three times. Write the complete sequence. How many actions occur? What would happen if the stopping instruction were missing?

Classroom dialogue

Ask: Which facts are given, and which would we have to assume? Learners mark relevant details before discussing answers.

Say: Predict first. Show the rule, information path or calculation that would produce the result. A correct guess is not yet an explanation.

Reveal reasoning one step at a time. Explain why a tempting alternative fails. Write units and denominators for arithmetic, trace conditions for decisions, and identify supporting sources for claims.

In pairs, one learner solves while the other checks evidence; exchange roles. Remove the worked answer before independent assessment.

Model these guided questions

From 3 under add 2: 3 true, 5 true, 7 false; two iterations and report 7. Under add 0: 3 true repeatedly, with no change and no report. Seeing 3 during that faulty run is not a returned result. For the exit, start 7 or any larger whole number checks zero iterations and reports that start. Start 6 checks crossing the boundary and reports 8 after one iteration.

Reduce help deliberately

Completion task: Use the same below 8 loop with add 2. Make separate runs from 8 and 9. Explain how many times the body runs and what each run reports. Why would adding 2 once be an error?

Teacher check: Both first tests are false. Each run has zero iterations, reporting its unchanged starting value: 8 or 9. Adding 2 once would execute the body despite a false first test.

Start by identifying the given inputs together. Leave the intermediate steps blank. If needed, model one step, then withdraw that help on the next step. Move to a full trace only when the partial trace is understood. For partners, alternate explainer and checker; collect a response from every learner before discussion.

Individual reasoning check

Use the worked case for Loops and stopping rules. Proposed explanation: “Every loop runs at least once”. Decide whether this explanation is supported. Point to the step or supplied fact that decides; explain your repair if needed.

Expected correction: Point to the test before the body. From 7 under below 7 the first test is false, so no update is permitted.

Collect explanations, not only yes/no votes. If a misunderstanding is common, re-model the relevant step for the class. If it affects a few learners, give a short targeted group explanation while others solve a more demanding variation.

Pictorial practice question

Trace a fresh start of 9. How many additions occur, and must the report equal 10?

Reasoned teacher answer

9<10 is true, so it becomes 12. Then 12<10 is false: one addition, report 12; equality with 10 is not required.

Changed-case reasoning: The loop runs zero times and reports 10. Its first condition is already false, so no addition happens.

Collect each learner’s explanation before discussion. Use the first missing connection between input, deciding step and result to choose support. This question is worked-case practice, not fresh mastery evidence.

Diagnose and reteach

CLAIM TO REPAIR Three repetitions always mean three actions.

For guessing, return to given facts and request a trace. For vocabulary without application, use one example and one non-example. For arithmetic errors, check the setup before the calculation. Finish with a different uncoached case before recording mastery.

Address these additional misconceptions

Every loop runs at least once: Point to the test before the body. From 7 under below 7 the first test is false, so no update is permitted.

The final value must equal the threshold: Trace start 6 under add 2 and below 7. The loop reports 8 because the stopping requirement is no longer below 7.

Tests and iterations are the same count: Count body executions separately and show the last false test with no body action.

A changing number guarantees a stop: Compare below 7 with not equal to 7 from 6 under add 2. Even numbers pass 7 without equalling it.

Independent question

Repeat clap then tap three times. Write the complete sequence. How many actions occur? What would happen if the stopping instruction were missing?

Clap, tap, clap, tap, clap, tap: six actions. Without a stopping instruction, the described repetition has no defined end.

Feedback

Ask the learner to find the evidence that challenges this claim: “Three repetitions always mean three actions.” Keep the first attempt and an uncoached retry separate.

Original transfer answer

Continue while stamped<5 AND another unstamped card exists. Counts are 0,1,2,3; stop because the stack is empty. Report three completed and two unavailable. A loop needs a progress update and a termination condition; it must not invent missing inputs.

Explanations for the additional workbook examples

W1 Trace every test

Start counter at 2. While counter is below 8, add 2. When false, report and stop. Record the value and result at every test, including the final false test. State the number of iterations and the reported value.

Tests: 2 true, 4 true, 6 true, 8 false. Three additions are three iterations. The loop reports 8; the fourth test does not run the body.

W2 Check the first test

Use the same below 8 loop with add 2. Make separate runs from 8 and 9. Explain how many times the body runs and what each run reports. Why would adding 2 once be an error?

Both first tests are false. Each run has zero iterations, reporting its unchanged starting value: 8 or 9. Adding 2 once would execute the body despite a false first test.

W3 Find the extra repetition

Start counter at 3. While counter is below 8, add 2. A learner writes values 3, 5, 7, 9, 11 and reports 11. Identify the first unauthorised update. Give the correct final test, reported value and iteration count.

After 7 becomes 9, the next test 9 below 8 is false. The update from 9 to 11 is unauthorised. Report 9 after three iterations, with test rows 3 true, 5 true, 7 true, 9 false.

W4 Transfer to a countdown

A paper countdown starts at 7. While remaining is above 1, subtract 2. When false, report and stop. Trace the run and count iterations. Repeat from 6 and from 1. Explain why the final value need not equal 1. What happens from 7 if subtract 2 is replaced by subtract 0?

From 7: 7 true, 5 true, 3 true, 1 false; three iterations, report 1. From 6: 6 true, 4 true, 2 true, 0 false; three iterations, report 0. From 1: first test false, zero iterations, report 1. Above 1 stops at 1 or below. Subtracting 0 from 7 leaves every test true, so that faulty run never reports.

W5 Test a proposed stopping rule

A procedure says start at 4; while counter is not equal to 9, add 2; report and stop. Write the first four values tested. Explain why the loop will not reach 9 using whole numbers. Suggest a changed condition that would stop once the counter reaches or passes 9, and trace that repaired run.

The first four values are 4, 6, 8, 10. Adding 2 to an even number always gives another even number, so the counter cannot become the odd number 9. Change the condition to while counter is below 9. Then 4 true, 6 true, 8 true, 10 false; three iterations and report 10.

Assess independent transfer

Selected case: A paper countdown starts at 7. While remaining is above 1, subtract 2. When false, report and stop. Trace the run and count iterations. Repeat from 6 and from 1. Explain why the final value need not equal 1. What happens from 7 if subtract 2 is replaced by subtract 0?

Selected case answer

From 7: 7 true, 5 true, 3 true, 1 false; three iterations, report 1. From 6: 6 true, 4 true, 2 true, 0 false; three iterations, report 0. From 1: first test false, zero iterations, report 1. Above 1 stops at 1 or below. Subtracting 0 from 7 leaves every test true, so that faulty run never reports.

Support and stretch

Use physical cards, spoken explanations and a three-stage drawing. Read aloud without giving the answer. Stretch: compare two mechanisms with the same visible output and explain what evidence distinguishes them.

Exit reflection

Bridge to the next week

Support and fresh reassessment

Let students move a token from the test card to the body and back. Use written true and false labels as well as arrows. Provide a separate tally box for body executions. Extension: explain why start 2, while not equal to 7 add 2 never reaches its reporting instruction with exact whole-number arithmetic.

W4 is secure when the learner traces the decrementing loop, includes zero iterations, accepts 0 as a valid final result from 6 and explains why subtract 0 cannot end the run from 7.
