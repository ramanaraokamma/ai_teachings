01. Project Problem and Success Test: the case

A fictional reading-break chooser needs a transparent contract. Supplied facts: Items have id text, minutes integer 0–30, interest integer 0–5. Request limit is integer 0–30.

Eligible if minutes<=limit; score=interest; highest wins; ties choose alphabetically smaller ID; invalid rows excluded and counted.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Specify inputs: Validate each row and request; keep rejected-row reasons. → Filter and rank: At limit 8: A(time8,interest3), B(9,5), C(6,3).

B is ineligible. → Expected output: A beats tied C by ID; report A and its score 3. → Acceptance cases: Also plan invalid request, no eligible item and equal-score cases.

Point to each numbered stage and explain which recorded input it uses.

03. Follow the evidence

Follow the evidence. Input | Local fictional records | Validate schema. Decision | Filter then score then tie rule | Explain selected item. Output | Suggestion or no eligible item | Teacher reviews

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Also plan invalid request, no eligible item and equal-score cases. Changed condition: Reduce the limit from 8 to 5. Expected result: Return no eligible item.
