01. Trace Tables: the case

A fictional reading-token jar starts with one token and gains three per round. Supplied facts: Python: total=1; for turn in range(4): total=total+3; after the loop print(total). The update is inside the loop; print is outside.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Initial state: Before the loop, total=1. → Iteration values: range(4) supplies turn values 0,1,2,3. → Updated totals: After each turn total is 4,7,10,13. → After the loop: Print 13 once, after all four updates.

Point to each numbered stage and explain which recorded input it uses.

03. Loop totals after each iteration

Loop totals after each iteration. First: turn = 0, total after update = 4. Second: turn = 1, total after update = 7. Third: turn = 2, total after update = 10. Fourth: turn = 3, total after update = 13.

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Print 13 once, after all four updates. Changed condition: Use range(0) instead of range(4). Expected result: The loop body never runs and the printed total is 1.

Reason: The iterable contains no turn values; the initial assignment still happened.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

The turn value labels an iteration; it is not the number added. The fixed update adds three each time. Four iterations take the total from 1 to 13.

Keeping print outside the loop produces one final display rather than four intermediate displays. Initialise total before the loop so a zero-iteration run still has a defined value.

Limit: This finite loop does not establish behavior of a while-loop with a different update or stopping condition.

Explain the case, then point to a limit on the claim.
