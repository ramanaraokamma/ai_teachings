01. Build a Paper Prototype: the case

A fictional team turns a storage-bin specification into movable instruction cards. Supplied facts: Bins X capacity 3 then Y capacity 7; valid count 1–9. Select first capacity at least count.

For request 4, write baseline Y before operating cards. Prototype cards mistakenly stop with X immediately.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Expected result: Baseline checks X then Y and expects Y for count 4. → Operate literally: Follow the current prototype cards without secretly repairing them. → Actual trace: Prototype stops at X; it never performs the capacity comparison. → Record mismatch: Expected Y, actual X: locate the missing check.

Point to each numbered stage and explain which recorded input it uses.

03. A paper run that can be checked

A paper run that can be checked. Request and version labels | Validate the two fields | Record pass or clarification. Marker at current row | Check time AND quiet | Record checks and next step.

First fit or end of list | Suggest or report no match | Record output and stop

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Expected Y, actual X: locate the missing check. Changed condition: Insert “if capacity is below count, continue” before accepting a bin. Expected result: The revised trace rejects X and accepts Y for 4.

Reason: 3<4 is true; 7<4 is false, so Y fits.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.
