Complete task and evidence

  • Security/privacy review maps assets, actors, actions, data flows and threats. Main G1 guide has an obvious fictional restricted marker; teacher-1 may read, learner-1 may not. A direct denial is insufficient if a query-only student-accessible cache stores/returns the guide. Both repaired direct/cache paths use trusted actor permission before lookup/context; learner denies with empty read trace, teacher allows.

    Request schema is exactly resource_id; role claims reject, unknown actors deny. Separate N1 note text belongs to learner-1 and assigned teacher-1 only; teacher-2 denies. Picture analytics needs revision counts, not private notes: two allowed revision-kind events yield revision_count 2, and a full-note event rejects. No note text or learner IDs are sent in that packet, yet tiny-group counts may remain identifying.

    Check linkability, readers and retention separately. Source instructions cannot grant authority, and happy-path checks do not test all misuse. Code uses copied fictional records/markers and no real secrets/accounts. It does not test all injection, retention or unlisted routes and provides no complete security/anonymity guarantee.
