01. Replication and reproduction: the case

Same records versus new experiment. A team first reruns a supplied analysis, then collects new records with the same protocol. Supplied facts: Original recorded correctness flags: [1,0,1,1]. Analysis counts correct cases. New independent set: [1,1,0,0]. Binary entries mean 1=correct and 0=incorrect.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Reproduce the analysis: Reusing the supplied four records gives 3/4=75%. → Repeat the protocol: The new four-record set gives 2/4=50%. → Compare purposes: The first checks computational reproduction; the second probes repeatability with new observations.

Point to each numbered stage and explain which recorded input it uses.

03. Different four-record datasets

Different four-record datasets. Units: correct cases out of 4; samples differ. Saved analysis: 3. New sample: 2.

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: The first checks computational reproduction; the second probes repeatability with new observations. Changed condition: The rerun of the original records outputs 2/4.

Expected result: Investigate code, version, input or scoring differences. Reason: The same fixed records should give the same deterministic count.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

Reusing data and collecting new data answer different questions. A different new-sample result can arise without a code error; inspect both protocols and variability.

Limit: Four-case samples are illustrative; neither result alone establishes broad reliability.
