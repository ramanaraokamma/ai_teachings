01. Missing Data: the case

A fictional catalogue records counts of available copies under a strict input contract. Supplied facts: Accept count only if type(value) is int and 0<=value<=8. Missing fields are invalid, and Booleans are not counts.

Rows have count 0, count 4, absent count, count "4", count True and count 9.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Retrieve carefully: Use row.get("count"); absent field gives None, distinct from 0. → Check exact type: Integers 0,4 pass; text "4", Boolean True and None fail. → Check range: Integer 9 fails maximum 8. → Report validation: Accepted counts [0,4]; four rows rejected with recorded reasons.

Point to each numbered stage and explain which recorded input it uses.

03. Follow the evidence

Follow the evidence. Recorded zero | 0 | Accept as a measurement. Absent or None | Unknown | Hold for review. Negative integer | Outside range | Reject under this schema

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Accepted counts [0,4]; four rows rejected with recorded reasons. Changed condition: Replace text "4" with integer 4 through an authorised conversion.

Expected result: Accepted values become [0,4,4]; three rows remain rejected. Reason: The converted value now satisfies both type and range checks.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

Testing if value would wrongly discard zero, which is a real valid count. Python’s isinstance(True,int) is true, so the stated exact-integer contract uses type(value) is int to reject Boolean input.

Keep missing, type-invalid and range-invalid reasons separate rather than turning every rejected value into zero. Limit: Type and range checks cannot confirm whether the real shelf count was measured accurately.

Explain the case, then point to a limit on the claim.
