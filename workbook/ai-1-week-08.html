01. Features: Useful Clues: the case

A fictional shelf accepts a craft box only if width is at most 6 cm and height at most 4 cm. Supplied facts: Boxes P=(6,4,stripes), Q=(7,4,stripes), R=(6,5,dots), S=(6,4,dots).

A green acceptance sticker is attached only after the shelf check.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Width check: P,Q,R,S have widths 6,7,6,6. → Height check: Their heights are 4,4,5,4. → Apply both limits: P and S fit; Q fails width; R fails height. → Reject a shortcut: The later sticker cannot be an input available before checking.

Point to each numbered stage and explain which recorded input it uses.

03. Dimensions determine shelf acceptance

Dimensions determine shelf acceptance. P stripes: Width cm = 6, Height cm = 4, Outcome = fits. Q stripes: Width cm = 7, Height cm = 4, Outcome = width fails. R dots: Width cm = 6, Height cm = 5, Outcome = height fails.

S dots: Width cm = 6, Height cm = 4, Outcome = fits.

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: The later sticker cannot be an input available before checking. Changed condition: Change Q’s width to 6 without changing its height. Expected result: Q fits the shelf.

Reason: Both dimensions now meet their limits, with equality allowed; stripe pattern does not change the rule.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

Comparing P with Q isolates width; comparing S with R isolates height. Comparing P with S changes pattern while both remain accepted. Under this declared policy, pattern is not a deciding feature.

A later acceptance sticker leaks the very answer the system should produce. Limit: These comparisons establish the written shelf rule, not the importance of pattern for unrelated tasks.

Explain the case, then point to a limit on the claim.
