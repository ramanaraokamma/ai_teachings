W1 · Explain the current example

Keep this task’s inputs,rule and response together.

Complete task and evidence

  • A queue separates accepting work from completing it. Main states are pending, running, completed and failed. Picture vocabulary queued/succeeded corresponds to pending/completed. A submission receipt proves acceptance; a worker acknowledgement is a separate signal after the declared durable completion step. Main job J commits a checked result then crashes before acknowledgement.

    Redelivery with the same ID and payload consults reliable completion evidence, returns the prior result and acknowledges without another effect: two deliveries, one mock effect. Unknown or running-only status requires reconciliation; same-ID changed payload is a conflict. Separate J12 receipt proves queued only; checked output permits succeeded.

    An observed pre-output crash permits failed status, while an unobserved crash may leave stale running status. No retry policy is implied. Reliable effect/status correspondence is an explicit assumption. The code is sequential in-memory fiction with copied snapshots; it implements no broker, durable commit, concurrency or exactly-once delivery. Losing history can lead to a repeated mock effect.
