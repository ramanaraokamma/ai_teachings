W1 · Explain the current example

Keep this task’s inputs,rule and response together.

Complete task and evidence

  • School service policy: trusted student may read student resources; trusted teacher may read student and teacher resources; no recognized trusted session or unknown role/resource classification denies. Main request comes from a trusted student session but carries role=teacher and asks to read a teacher guide. Use trusted session role, deny before reading guide body, and leave session unchanged.

    Client-written roles never promote authority. Authentication establishes identity/session context; authorization checks action/resource permission using trusted policy. Local code starts with trusted fixtures, not a real login. Separate museum policy: verified volunteer Jo may read C but not edit C; verified curator with edit permission passes that gate, subject to remaining checks.

    Permission is not executed editing. No real authentication protocol, expiry, writes or deployment are implemented. Later school role decisions apply the already taught policy; collect individual reasoning and reserve a fresh action/resource case for new-transfer claims.

  • Explain the weekly mechanism in your own words. Use the worked scenario to name its input, decision rule and output.
