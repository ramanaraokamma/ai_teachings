01. Algorithms as Recipes: the case

A fictional paper badge machine transforms an initial score using an ordered recipe. Supplied facts: Start score=3. Recipe A: double, add 4, subtract 1, report.

Recipe B swaps the first two operations but keeps the same starting score.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Start: Both runs begin at 3. → Recipe A: 3 → 6 after doubling → 10 after adding 4 → 9 after subtracting 1. → Recipe B: 3 → 7 after adding 4 → 14 after doubling → 13 after subtracting 1. → Compare outputs: Same operations, different order: outputs 9 and 13.

Point to each numbered stage and explain which recorded input it uses.

03. Changing instruction order

Changing instruction order. Recipe A: Start = 3, After step 1 = 6, After step 2 = 10, Report = 9. Recipe B: Start = 3, After step 1 = 7, After step 2 = 14, Report = 13.

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Same operations, different order: outputs 9 and 13. Changed condition: Change the starting score to 0 for both recipes. Expected result: A reports 3 and B reports 7. Reason: A: 0→0→4→3. B: 0→4→8→7.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

Every instruction reads the current score, not the original one unless explicitly told to. In B, doubling also doubles the added 4. In A, the extra 4 is added after doubling.

The final difference of 4 follows from that order, not from different starting data. Limit: One traced input checks one run; it does not establish every recipe is equivalent or validate an entire program.

Explain the case, then point to a limit on the claim.

Write the sorter’s steps in order, showing which values each step updates so a partner can reproduce the result. Draw your input, deciding step, result and limit.
