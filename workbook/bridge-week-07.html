01. Lists and indexing: the case

Indexes are positions, not values. A list of shelf counts is read by position. Supplied facts: Python 3: counts=[6,1,8]; print(counts[0]); print(counts[-1]); print(len(counts)).

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

Draw positions: Indexes 0,1,2 contain 6,1,8 respectively. → Read two positions: Index 0 returns 6; index -1 returns the final value 8. → Check length boundary: Length is 3, but index 3 is beyond the final valid positive index 2.

Point to each numbered stage and explain which recorded input it uses.

03. Zero-based list positions

Zero-based list positions. Stored counts: Index 0 = 6, Index 1 = 1, Index 2 = 8.

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Length is 3, but index 3 is beyond the final valid positive index 2. Changed condition: Replace the second print with print(counts[3]).

Expected result: The first print shows 6, then IndexError stops the script before the length print. Reason: The attempted position does not exist.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

List positions begin at zero. A negative index counts from the end; the list length counts entries and is not itself a valid positive index for the final entry.

Limit: A valid position does not establish that the stored count is accurate; empty lists also have no final element to read.

Explain the case, then point to a limit on the claim.
