01. Repeating Efficiently: the case

A fictional paper counter advances through a display until its condition becomes false. Supplied facts: Start at 2. While the current counter is below 10, add 3. Test before each addition; report when the condition is false.

Point to the given fact that matters most. Explain why it matters.

02. Follow the deciding steps

First test: 2<10 is true: update to 5. → Repeat: 5<10: update to 8. 8<10: update to 11. → Stop test: 11<10 is false; do not add again. → Report: Final counter 11 after three additions.

Point to each numbered stage and explain which recorded input it uses.

03. Condition checks before additions

Condition checks before additions. Check 1: Current = 2, Below 10? = true, Next = 5. Check 2: Current = 5, Below 10? = true, Next = 8. Check 3: Current = 8, Below 10? = true, Next = 11.

Check 4: Current = 11, Below 10? = false, Next = stop.

Read the labels and values. Explain the relationship the model shows.

04. Change one thing. Trace what follows.

Original case: Final counter 11 after three additions. Changed condition: Start at 10 instead of 2. Expected result: The loop runs zero times and reports 10.

Reason: Its first condition is already false, so no addition happens.

Predict before checking the worked changed-case result. Name what changed and what the supplied facts allow you to conclude.

05. Connect the explanation to its limit

The condition checks whether to do the next update; it does not constrain every resulting value to stay below 10. The final 11 is therefore allowed by this procedure.

Record both the condition and counter to distinguish a correct stop from an assumed endpoint. Limit: This loop stops because positive increments eventually cross the limit. Other updates can fail to make progress.

Explain the case, then point to a limit on the claim.
